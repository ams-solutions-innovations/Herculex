## Additional confirmed fixes from the audit

- Raw cloud pull/deletion SQL did not notify Drift readers. Cloud changes now refresh observing screens, widgets and watch-plan inputs. Unknown future server columns are ignored by older versions of this updated sync implementation.
- Two devices creating a nutrition target with the same scope/start date could violate the local unique key. Targets now converge on the user/scope/start key, preserve pending local changes until pushed, adopt the server identity when appropriate, and use synchronized deletion markers.
- Reopening an already accepted recovery adjustment could reduce the same workout again. The accepted resolved plan is recognized and not repeatedly reduced.
- Multiple accepted overrides for one scheduled occurrence could make plan resolution throw “Too many elements”. The newest accepted override is selected deterministically.
- The public friendship membership helper exposed arbitrary relationship lookups. The deployed function now requires the caller to be one of the two people; anonymous execution is revoked. Other inspected buddy helpers already enforce authentication/participation.
- Workout-history tiles lacked their own Material surface, hiding ink effects and triggering a Flutter debug assertion after finishing a workout. The surface is corrected.
- Existing workout keyboard/finish tests performed native database IO inside fake time and could hang. Their fixtures and platform mocks were corrected; the complete suite now terminates.

## Gemini operational blocker

A real version-28 barcode request at 13:01 UTC received **429 from both the primary and fallback Google models**, then a controlled 503 from Herculex. The fallback and two-attempt cap behaved as designed; a successful authenticated AI request has not been demonstrated since these changes.

Read-only inspection of the signed-in Google AI Studio account showed its Default Gemini Project as **Prepay required**, its billing type as inactive/unsupported, and Google Cloud reported **“This billing account is closed.”** The project is linked to that closed billing account. The account owner must resolve the billing status in [Google Cloud Billing](https://console.cloud.google.com/billing). The billing account was not changed, reopened or charged during this task. Verify that the production Gemini key belongs to the intended, funded project when billing is restored.

Version 29 returns a specific provider-capacity error for this condition and retains the user's input. Application retries cannot repair a closed billing account.
