<objective>
Lay the foundation Wave 1-4 build on: the `ProgramSlotExplanations` drift table (schema v42,
local-only per the resolved A1 decision), the `SelectionExplanation` domain result type that later
planner logic will construct and this table will persist, a shared `JointModel.excludedMusclesFor`
helper so injury-driven muscle exclusion has exactly one implementation, and a standalone
`EmptySlotNotice` presentational widget for D-04's visible-gap UI. None of these wire into the actual
planner or program review screen yet (that's Waves 1-4) — this plan only defines the contracts and
proves each one works in isolation, per the "interface-first" ordering rule.

Purpose: every later plan in this phase either writes to `ProgramSlotExplanations`, constructs a
`SelectionExplanation`, calls `JointModel.excludedMusclesFor`, or renders `EmptySlotNotice`. Defining
these first means Wave 1+ plans consume a finished contract instead of improvising one mid-refactor.
Output: a new drift table + migration (schema v42), two new small domain files, one new presentation
widget, and three new/extended test files proving each in isolation.
</objective>
