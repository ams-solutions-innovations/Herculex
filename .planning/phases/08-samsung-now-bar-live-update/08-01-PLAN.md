<objective>
Replace the reflective post-build extras hack in the ongoing workout renderer with real Android 16 Live Update API calls, so `hasPromotableCharacteristics()` reports true and One UI can promote the workout into the Now Bar.
</objective>

<read_first>

- `android/app/src/main/kotlin/com/ams/herculex/nowbar/OngoingWorkoutSurfaceRenderer.kt` — the file being rewritten; `show()` is at line 52, the reflective helpers at 222-272.
- `android/app/src/main/kotlin/com/ams/herculex/nowbar/LiveUpdatesCapability.kt` — `isPlatformSupported` is `SDK_INT >= 36`; branch on it rather than introducing a new constant.
- `android/app/src/main/kotlin/com/ams/herculex/nowbar/OngoingWorkoutSurfaceSnapshot.kt` — the typed fields available to the builder (`collapsed.title/value`, `expanded.rows/actions`, `sessionId`, `targetSetId`, `startedAtEpochMillis`).
- `android/app/src/main/kotlin/com/ams/herculex/nowbar/OngoingWorkoutSurfaceFeedback.kt` — writes the same extras constant at line 74 and reuses notification id 1 at line 118.
- `docs/now-bar-native-adapter-contract.md` — the renderer-boundary rule: only the renderer changes, never the channel, parser, receiver, queue or Dart command logic.
- `lib/theme/app_theme.dart` — source of the accent colour for `setColorized`.

</read_first>

<tasks>

1. Add an API 36+ branch to `AndroidOngoingWorkoutSurfaceRenderer.show()`, selected by `capability.isPlatformSupported`. Build it with the platform `android.app.Notification.Builder(appContext, CHANNEL_ID)` rather than `NotificationCompat.Builder` — the installed androidx version does not expose the promoted-ongoing setters, which is the reason the current code resorted to reflection.

2. On the API 36+ branch call the real setters directly, with no reflection: `requestPromotedOngoing(true)`; `setShortCriticalText(...)` fed from the snapshot (set counter such as `"3/5"`, or `collapsed.value` when no set counter is present); `setStyle(Notification.ProgressStyle())` with segment count taken from the snapshot's total sets and progress from the current set index; `setColorized(true)` with `setColor(...)` from the app accent. Keep `setOngoing(true)`, `setWhen(snapshot.startedAtEpochMillis)`, `setUsesChronometer(true)`, `setCategory(Notification.CATEGORY_WORKOUT)`, `setVisibility(Notification.VISIBILITY_PRIVATE)`, `setSmallIcon(R.mipmap.ic_launcher)`, `setContentIntent(openWorkoutIntent(...))`, and the actions from `actionPendingIntents` in `snapshot.expanded.actions` order.

3. Do **not** call `setLocalOnly(true)` or `setSilent(true)` on the API 36+ branch. Both can disqualify a notification from promotion. `setOnlyAlertOnce(true)` stays.

4. Delete `requestPromotedOngoingIfAvailable()`, `isRequestPromotedOngoing()`'s reflective lookup, and the `EXTRA_REQUEST_PROMOTED_ONGOING` / `"android.requestPromotedOngoing"` constant. Rewrite `hasPromotableCharacteristicsIfAvailable()` and `activeNotificationIsPromotedOngoing()` as direct `Notification.hasPromotableCharacteristics()` and `Notification.FLAG_PROMOTED_ONGOING` calls guarded by `Build.VERSION.SDK_INT >= 36`, returning false below that. These two values are the phase's primary success signal, so they must not be swallowed by `runCatching`.

5. Keep the existing `NotificationCompat.Builder` + `BigTextStyle` path unchanged for devices below API 36, minus the deleted extras write. Both branches must post the same `NOTIFICATION_ID` on the same `CHANNEL_ID`, and `clear()` is unchanged.

6. In `OngoingWorkoutSurfaceFeedback`: remove the `extras.putBoolean(EXTRA_REQUEST_PROMOTED_ONGOING, true)` write and its constant, and give the feedback notification its own id distinct from `1` so it cannot overwrite the Live Update. Leave its channel, content and action wiring otherwise unchanged.

7. Extend the renderer's `lastDiagnostics` map: report `"style"` as `"ProgressStyle"` on the API 36+ branch (and `"BigTextStyle"` below it), and add a `"shortCriticalText"` entry carrying the string actually passed to `setShortCriticalText`. Keep every existing diagnostics key — `OngoingWorkoutSurfaceBridge`'s Dart parser and `test/ongoing_workout_surface_bridge_test.dart` assert on them.

8. Keep the two existing `Log.i(TAG, "diagnostics event=posted ...")` and `Log.d` lines emitting the same keys (`posted`, `requestedPromoted`, `promotable`, `systemPromoted`, `channelImportance`, `actions`, `rows`, `controls`), because `docs/now-bar-workout-proposal.md` documents them as the device-test contract.

</tasks>
