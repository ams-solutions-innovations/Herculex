# Plan 15-03: Calendar Schedule Launch Disambiguation & Tab Navigation

<threat_model>
## Threat Model (ASVS L1)
- **Threat T-15-05 (Data Integrity / Duplicate Session Collisions):** When multiple workouts are scheduled on the same date (e.g. morning strength + evening conditioning), launching or resuming the second workout inadvertently triggers or resumes the first workout due to date-only queries with `limit(1)`. Repeatedly tapping Resume spawns duplicate `WorkoutSessions` rows and desynchronizes workout history.
- **Mitigation:** Strict enforcement of keying all schedule actions by explicit `scheduleId` in `ScheduledWorkoutService.startScheduledWorkoutById` and `workoutForSchedule`. Resume operations must be strictly idempotent: if an open session already exists for the scheduled workout, return its session ID without inserting a new `WorkoutSessions` row or mutating foreign keys.
- **Threat T-15-06 (Unintended State Mutation on Preview):** Tapping "View workout" on future or past scheduled items accidentally writes a session or modifies schedule status.
- **Mitigation:** Enforce that `previewScheduledWorkout` is strictly read-only and never issues database mutations.
</threat_model>
