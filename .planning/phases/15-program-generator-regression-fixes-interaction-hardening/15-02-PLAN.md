# Plan 15-02: Opaque Replacement Sheets & Synchronized Active Workout Keyboard Obstruction

<threat_model>
## Threat Model (ASVS L1)
- **Threat T-15-03 (Accidental State Corruption / Premature Workout Completion):** While a user is typing a weight, reps, or RPE value into a set input field, the software keyboard animates or leaves the Finish Workout button partially visible or hit-testable. The user accidentally taps the Finish button or Home navigation bar instead of a keyboard key, aborting the session prematurely or navigating away during high physical fatigue.
- **Mitigation:** Unify input focus and keyboard visibility under a single synchronized provider. On input focus or `viewInsets.bottom > 0`, immediately set `bottom: -140` / `bottom: -120` on Finish/Add buttons and navigation bar, wrapped in `ExcludeSemantics(excluding: true)` and `IgnorePointer(ignoring: true)`.
- **Threat T-15-04 (UI Bleed-Through / Legibility Failure):** Replacement exercise bottom sheets rendering transparently because the parent scaffold background is transparent. In public or gym lighting conditions, the background exercise cards bleed through the sheet text, making candidate selection illegible.
- **Mitigation:** Enforce canonical `HxSheet` with `context.hx.surfaceContainer` on all exercise replacement modals (`ExerciseReplacementSheet` and `SmartSubstitutionSheet`), guaranteeing full opacity and surface contrast in both light and dark themes.
</threat_model>

   - Watch `workoutInputFocusedProvider`:
     ```dart
     final inputFocused = ref.watch(workoutInputFocusedProvider);

     ```

     - Floating action bar AnimatedPositioned sets `bottom: -140`.
     - `ExcludeSemantics(excluding: keyboardOpen)` excludes controls from accessibility.
     - `IgnorePointer(ignoring: keyboardOpen)` disables hit-testing.

   - Watch `workoutInputFocusedProvider`:

         hasActiveSession &&
         (View.of(context).viewInsets.bottom > 0 || workoutInputFocused);

   - When `hideWorkoutChrome` is true:
