<objective>
Replace the manual "record on hardware, hand-copy CSVs" procedure in 10-02's Task 5 with an in-app debug tool: a checklist of the 11 required motion-trace fixtures with recorded/missing status and overall sufficiency, and a capture flow that lets the developer record each one during a real workout — writing files in the exact CSV+sidecar format 10-02's fixture corpus already expects.

Purpose: fixture recording is the phase's standing blocker (10-02 Task 5, `user_setup` in that plan's frontmatter). It cannot be automated — REP-06 requires *recorded* traces — but the mechanics of tagging, ground-truth entry and file writing can be, so the developer can capture the corpus opportunistically across several real workouts instead of a single dedicated hardware session.
Output: `fixture_corpus.dart` (the closed list of 11 required fixtures and sufficiency logic), `fixture_recorder.dart` (on-device file I/O matching 10-02's schema), a small additive hook on `RepCaptureService`, a debug-only screen under the existing admin area, and pure-logic tests.

This plan does not close REP-06 and does not touch `test/fixtures/motion/` in the repo — it produces files in app-local storage that the developer still exports and commits by hand. 10-02's Task 5 automated check (`test/fixtures/motion/*.csv` count and `synthetic: false`) is unchanged and remains the actual gate.

**REP-04 boundary:** `RepCaptureService`'s raw-sample discard is the phase's core privacy property. This plan adds one optional field, `debugRawTraceObserver`, defaulting to `null` and touched only by this plan's debug screen. No production code path — consent flow, live counter, review sheet — ever sets it. The discard-in-`finally` behaviour from 10-03b is unchanged; the observer, when non-null, is *also* called with the trace before the buffer is cleared, not instead of clearing it.
</objective>

enum FixtureRecordState { missing, recorded, needsRedo }
