<objective>
Build the single authoritative rep-cycle detector as pure Dart functions over a list of samples — no plugins, no async, no database — plus the recorded-trace fixture corpus that proves it counts correctly and resists false positives.

This is `autonomous: false`: real motion traces must be recorded by a human before the accuracy bar can be met (see 10-CONTEXT risks).
</objective>

<tasks>

1. `motion_sample.dart`: `MotionSample(int tMs, double x, double y, double z)` and `MotionTrace` holding an ordered `List<MotionSample>` plus `sensorType`. Add `MotionTrace.resampled({int hz = 50})` — linear interpolation onto a fixed grid. **Every input goes through resampling**, so live capture at a jittery `SENSOR_DELAY_GAME` and a fixture CSV take byte-identical code paths downstream. Detector correctness must never depend on delivery rate.

2. `rep_detector.dart` — the algorithm, deliberately built from primitives that are trivial to reason about in a test rather than from a filter-design library:

   a. Magnitude `sqrt(x²+y²+z²)` per sample. For `accelerometer` (non-linear) traces, first subtract a 2-second centred moving average to remove gravity.

   b. Smooth with a 5-tap centred moving average.

   c. Detrend against a 5-second trailing moving average; call the result the *activity signal*.

   d. Adaptive threshold: a candidate peak must exceed `mean + k·stddev` of the trailing 5 s of the activity signal, `k` defaulting to 1.2.

   e. A **rep is a full cycle** — trough → peak → trough — where both excursions exceed an amplitude gate set at 40 % of the running median cycle amplitude. Counting bare peaks is what makes walking register as reps; requiring a closed cycle with a symmetric amplitude gate is the primary false-positive defence.

   f. Refractory period: reject a cycle shorter than `minPeriodMs` (default 800 ms) or longer than `maxPeriodMs` (default 8000 ms). Defaults differ per `RepMovement` — dips are faster than pull-ups; put both in a `RepDetectorConfig` with named per-movement constructors rather than scattering literals.

   g. Per-rep confidence in 0–1 from normalised amplitude relative to the set median and period regularity relative to the running median period.

   h. Set-level confidence: the fraction of reps clearing a per-rep floor of 0.5, penalised for any inter-rep gap exceeding 2× the median period (a gap means a probable miss).

   Output `RepDetectionResult(repCount, perRepConfidence, setConfidence, cyclePeriodsMs, cycleAmplitudes, missedRepSuspected)`. Pure, synchronous, no I/O.

3. `rep_features.dart`: derive the calibration feature vector from a `RepDetectionResult` — mean rep period, rep-period coefficient of variation, normalised mean amplitude, final-rep period ratio (last period ÷ median of the first three), amplitude decay ratio (last amplitude ÷ median of the first three). Provide `toJson`/`fromJson`; this is the `featuresJson` payload 10-01's `RepSetObservations` stores and 10-05 trains on. Version the JSON with a `v` key from day one — 10-05 must be able to discard feature vectors from an older detector rather than train on incomparable numbers.

   Guard the ratio features: with fewer than 4 reps they are undefined, so emit null rather than a garbage value. 10-05 must handle nulls, not receive fabrications.

4. `tool/synthesize_motion_trace.dart`: generates deterministic synthetic traces from parameters (rep count, period, amplitude, jitter, noise floor, optional walking segment). This is for **CI coverage of edge cases and regressions only** — it cannot substitute for recorded traces, because a synthetic sine wave is exactly the signal any peak counter gets right.

5. Record and commit the fixture corpus under `test/fixtures/motion/` as CSV (`t_ms,x,y,z`), each with a sidecar `.json` holding ground-truth rep count, movement, source, placement, sensor type and a one-line description. Minimum corpus:

   | Fixture | Purpose |
   |---|---|
   | `pullup_wrist_clean_8reps` | baseline accuracy |
   | `pullup_wrist_grinder_5reps` | slowing final reps, uneven cadence |
   | `pullup_wrist_kipping_10reps` | high-amplitude noise between reps |
   | `dip_wrist_clean_12reps` | baseline, faster cadence than pull-ups |
   | `dip_wrist_partial_rom_10reps` | amplitude gate under shrinking ROM |
   | `ringdip_wrist_8reps` | the least stable eligible movement |
   | `pullup_phone_pocket_8reps` | phone source, different placement |
   | `noise_walking_60s_0reps` | false-positive resistance |
   | `noise_regrip_rest_45s_0reps` | re-gripping and resting between sets |
   | `pullup_wrist_interrupted_6reps` | capture cut mid-set |

   `test/fixtures/motion/README.md` documents the CSV format and exactly how to record a new trace, so the corpus can grow without re-deriving the procedure.

6. `test/rep_detector_test.dart` — table-driven over every fixture:
   - Counted reps within ±1 of ground truth on all clean fixtures, exact on `pullup_wrist_clean_8reps` and `dip_wrist_clean_12reps`.
   - **Both noise fixtures count exactly 0 reps.** This is a hard assertion, not ±1.
   - `pullup_wrist_grinder_5reps` yields a final-rep period ratio > 1.2 (the feature exists and is measurable) while the detector still counts 5.
   - `pullup_wrist_partial_rom` / `dip_wrist_partial_rom_10reps` produce reduced set confidence but a correct count.
   - `pullup_wrist_interrupted_6reps` sets `missedRepSuspected` and lands below the 0.5 confidence floor.
   - Determinism: running the detector twice over the same trace returns identical output.
   - Resampling invariance: a trace decimated to 30 Hz and one at 50 Hz produce the same rep count.

7. `test/rep_features_test.dart` — ratio features are null below 4 reps; JSON round-trips; the `v` key is present and a mismatched `v` is rejected by `fromJson`.

</tasks>
