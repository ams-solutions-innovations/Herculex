<objective>

  <action>
Create `lib/features/reps/domain/rep_detector.dart` with `RepDetector.detect(MotionTrace trace, {RepDetectorConfig config})`, built from primitives that are trivial to reason about in a test rather than from a filter-design library. `detect` calls `trace.resampled(hz: 50)` itself so no caller can bypass the grid.

Pipeline: (a) magnitude `sqrt(x*x + y*y + z*z)` per sample, and for `sensorType == 'accelerometer'` first subtract a 2-second centred moving average to remove gravity. (b) Smooth with a 5-tap centred moving average. (c) Detrend against a 5-second trailing moving average; call the result the *activity signal*. (d) Adaptive threshold — a candidate peak must exceed `mean + k * stddev` of the trailing 5 s of the activity signal, with `k` defaulting to 1.2. (e) A **rep is a full cycle**: trough to peak to trough, where both excursions exceed an amplitude gate set at 40 % of the running median cycle amplitude. Counting bare peaks is what makes walking register as reps; requiring a closed cycle with a symmetric amplitude gate is the primary false-positive defence. (f) Refractory period — reject any cycle shorter than `minPeriodMs` or longer than `maxPeriodMs`. (g) Per-rep confidence in 0-1 from normalised amplitude relative to the set median and period regularity relative to the running median period. (h) Set-level confidence — the fraction of reps clearing a per-rep floor of 0.5, penalised for any inter-rep gap exceeding 2x the median period, and set `missedRepSuspected = true` when such a gap exists.

Put every threshold in `RepDetectorConfig` with named per-movement constructors `RepDetectorConfig.pullUp()` (`minPeriodMs: 800`, `maxPeriodMs: 8000`) and `RepDetectorConfig.dip()` (faster cadence, so a shorter `minPeriodMs`), plus `RepDetectorConfig.forMovement(RepMovement)`. Do not scatter numeric literals through the pipeline — the exact tap counts and constants are Claude's discretion per 10-CONTEXT, provided the Task 6 fixture bar is met, but they must all be named config fields so a future tuning pass has one place to touch.

Return `RepDetectionResult(repCount, perRepConfidence, setConfidence, cyclePeriodsMs, cycleAmplitudes, missedRepSuspected)`. Pure and synchronous: no `async`, no I/O, and the file's only imports are `dart:math` and the two sibling domain files.
  </action>
