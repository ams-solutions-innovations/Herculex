<objective>
Ship the user-facing surface: a consent screen that is the only way to turn the feature on, a per-exercise toggle, a live counter during the set, and a review sheet where the user confirms or edits every proposed value. Plus the static test that makes "the tracker cannot write a set" a checked property.
</objective>

<read_first>

- `lib/features/workouts/presentation/active_workout_view.dart` — the set card and its completion handler; this is the **only** place `updateSet` may be called from for tracked sets. Read the whole set-row build before inserting anything.
- `lib/features/workouts/data/workouts_repository.dart:858` — `updateSet`'s signature; `reps`, `rpeX10`, `isCompleted` and `completedAt` are what must stay user-driven.
- `lib/features/health/presentation/health_integrations_view.dart` — the repo's existing pattern for a permissioned, opt-in integration screen with a privacy explanation. Match its structure and tone rather than inventing a new one.
- `lib/features/nutrition/presentation/gemini_photo_analysis_dialog.dart` — the established "AI proposed this, you must review before it is logged" flow from Phase 6. The review sheet should feel like a sibling of this, not a new idiom.
- `lib/app/router.dart` — route registration.
- `10-CONTEXT.md` — the `TrackerState` table; every state in it needs a rendering.

</read_first>

<tasks>

1. `rep_tracking_consent_view.dart` — the dedicated consent/onboarding screen, reachable from Profile → integrations. It is the **only** place `grantConsent()` is called. Content:
   - What is measured: accelerometer motion during a set you explicitly start.
   - Where it is processed: on your watch and phone. Raw motion never leaves your devices and is discarded when the set ends.
   - What is kept: a summary of each confirmed set (cadence, consistency, your confirmed reps and RPE).
   - What it will never do: complete, save or change a set on its own.
   - That it is a training aid, not a medical or safety device.
   - Sensor source picker (`wrist` / `phone`), and for `phone` a **required** placement selection — the primary action stays disabled until placement is chosen (REP-02).
   - A revoke control that calls `revokeConsent()` and states plainly that it deletes all stored calibration data.

2. Per-exercise opt-in: in the active workout exercise options for an eligible slug, a toggle calling `setExerciseEnabled`. When consent has not been granted, the toggle is replaced by a link to the consent screen — never a silent no-op, and never an inline consent shortcut.

3. `rep_tracker_panel.dart` — the in-set surface, rendered inside the active set card only when `repTrackingEnabledForProvider` is true. Renders each `TrackerState`:
   - `ready` → a "Start tracking" button. **The user starts it. It never auto-starts on set start.**
   - `tracking` → live count, a confidence bar, and a stop button. Where the source is the wrist, label the number "provisional" (10-03 note: this is the Kotlin counter, not the authoritative one).
   - `countOnly` → count shown, RPE area shows a short plain reason ("not enough confirmed sets yet" / "placement changed" / "low signal quality").
   - `manual` → collapses to today's manual entry with the reason stated.
   - `disabled` → renders nothing at all, no placeholder.

4. `rep_review_sheet.dart` — opens when the user ends the set, **before** anything is written:
   - Shows the proposed rep count as an **editable field pre-filled with the suggestion**, never a read-only confirmation.
   - Shows suggested RPE only when 10-05's gate passes; otherwise the RPE field is present, empty and unsuggested.
   - Shows detected rep count vs. confidence, and where the two counters disagreed by more than 1 rep, shows the authoritative count with a lowered confidence band (10-CONTEXT).
   - A "how this was measured" expander: source, placement, sensor type, sample coverage, and whether calibration was applied.
   - Primary action `Save set` calls the existing completion handler in `active_workout_view.dart` with the values **currently in the fields**, then calls `recordObservation(...)` with detected vs. confirmed values. Order matters: the set is written first, and the observation records what the user actually confirmed.
   - Dismissing the sheet without saving leaves the set untouched and records no observation.

5. Wire the panel and sheet into `active_workout_view.dart`. The insertion must be additive: for a non-eligible exercise, or with consent off, the set card renders exactly as it does today. Do not restructure the set row.

6. `test/rep_tracker_write_boundary_test.dart` — the REP-03 enforcement, a static source test:
   - Reads every `.dart` file under `lib/features/reps/` and asserts none contains `WorkoutsRepository`, `updateSet`, `SetEntriesCompanion`, or `db.update(`.
   - Asserts `lib/features/reps/` imports nothing from `lib/features/workouts/data/`.
   - Fails with a message naming the offending file and the rule, so a future contributor understands *why* rather than deleting the test.

7. `test/rep_tracker_widget_test.dart`:
   - `disabled` renders nothing.
   - `ready` renders a start control and no count.
   - `countOnly` renders a count and no RPE suggestion.
   - `manual` renders the manual entry path and a reason string.
   - The review sheet's rep field is editable and pre-filled; editing it and saving passes the **edited** value, not the detected one.
   - Dismissing the review sheet writes nothing — assert against a fake repository that `updateSet` was never called.
   - With consent revoked mid-session, the panel disappears on the next build.

</tasks>
