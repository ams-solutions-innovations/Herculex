# Phase 22 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

> **Scope note:** This is not a new-screen phase. It is an incremental extension of three
> already-live surfaces inside `block_builder_view` (Flutter, not web/shadcn): the
> specialization bottom sheet, the Weeks bottom sheet, and the Create-time guardrail path,
> plus a new live-preview surface reusing `ProgramMuscleVolumeCard`'s pattern. `shadcn`/React
> tooling in this agent's default checklist does not apply — Herculex is Flutter/Material with
> its own `lib/design_system/` token system (`HxColors`/`HxSpace`/`HxRadius` via `context.hx`,
> `HxSheet`). This contract expresses the shadcn-oriented template's fields in that system's
> terms.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Flutter/Material, not a web/shadcn project) |
| Preset | not applicable |
| Component library | `lib/design_system/components/` — `HxSheet` (bottom sheets), `AlertDialog` (info dialogs), house `_sheetOptionCard` picker pattern |
| Icon library | `Icons.*` (Material Symbols, `_rounded` variants used throughout this file family) |
| Font | App default `ThemeData.textTheme` (Herculex does not set a custom font family in this feature — inherited from `app_theme.dart`) |

**Token source of truth:** `lib/design_system/tokens/hx_colors.dart` (`HxColors`, resolved via
`context.hx.*`) and `lib/design_system/tokens/hx_geometry.dart` (`HxSpace`, `HxRadius`).
**Do not use `AppColors.*` or literal `Color(0x...)` in any new widget this phase touches** —
the active `docs/ui-rework/ROADMAP.md` Phase 9 track is deleting the `AppColors` shim
app-wide, and Phase 27's precedent widgets (`AiBriefRejectionBanner`, `AiDayRationaleCard`,
both in `lib/features/programs/presentation/widgets/`) already establish `context.hx` +
`HxSpace`/`HxRadius` as the house pattern for new code inside this otherwise-legacy-`AppColors`
file family. `step_parameters_specialization.part.dart` and `dialogs.part.dart` still read
`AppColors.*` today (pre-existing, out of this phase's cleanup scope) — new code added by this
phase must not add more `AppColors.*` call sites, but is not required to migrate the
surrounding existing lines.

## Spacing Scale

Herculex's token scale (from `HxSpace`, not the generic 8-point default — use these exact
constants, not raw pixel literals):

| Token | Value | Usage |
|-------|-------|-------|
| `HxSpace.x1` | 4px | Icon-to-text gap inside a banner/card row |
| `HxSpace.x2` | 8px | Compact vertical gaps (banner heading → body) |
| `HxSpace.x3` | 12px | Banner/card padding, row gaps |
| `HxSpace.x4` | 16px | Card padding, default section gaps |
| `HxSpace.x5` | 20px | Sheet horizontal padding (matches existing `step_parameters_specialization.part.dart` `EdgeInsets.only(left: 20, right: 20, ...)`) |
| `HxSpace.x6` | 24px | Section-to-section spacing |
| `HxSpace.x8` | 32px | Major layout gaps (not expected to be needed this phase) |
| `HxSpace.x10` | 40px | Page-level spacing (not expected to be needed this phase) |

Exceptions: the existing specialization modal and Weeks/Length picker use ad-hoc pixel
literals (`SizedBox(height: 6)`, `SizedBox(height: 18)`, etc.) rather than `HxSpace` tokens —
this is pre-existing and out of scope to retrofit. **All new spacing this phase adds (the
sticking-point-aware helper copy, the timeline warning banner, the volume-floor warning) must
use `HxSpace` constants**, not new literals, per the Phase 27 precedent.

## Typography

Herculex derives type from `Theme.of(context).textTheme` (Material 3 type scale), not a fixed
custom px table. Declared roles for this phase's new UI, matching the existing modal/sheet/card
patterns exactly. **Two weights total** for this phase's typography budget:

| Role | Style source | Weight | Usage |
|------|------|--------|-------------|
| Sheet/dialog title, section/banner heading | `theme.textTheme.titleLarge` (title) / `titleSmall` (banner heading) | `FontWeight.w700` | "Primary lift specialization" heading (existing, unchanged); new warning banner headings (timeline, kg-increase, volume-floor) — matches `AiBriefRejectionBanner`'s exact heading style |
| Body / helper copy / list rows | `theme.textTheme.bodySmall` (helper/body) / `bodyMedium` (rows) | inherited (regular) | Sticking-point helper text, warning body text, volume-floor detail lines, and the volume-floor live-preview's muscle-group row labels (this phase's new embedded instance of the row shell renders these at regular weight, not the `w600` used by the pre-existing standalone `ProgramMuscleVolumeCard`) |

Line height: not independently overridden — inherit `ThemeData.textTheme`'s defaults (Material
3 defaults to ~1.2–1.5 depending on role). No new line-height token is introduced this phase.

### Typography Exceptions

None. Every render site this phase authors or touches uses exactly the 2 weights declared
above — `FontWeight.w700` for headings, regular (inherited) for everything else. This
includes the new volume-floor live-preview surface: the pre-existing, already-shipped
`ProgramMuscleVolumeCard._buildMuscleRow` renders its row labels at `FontWeight.w600` in its
existing standalone usage elsewhere in the app (e.g. `program_preview_view.dart`), but this
phase's new embedded/live-preview instantiation of that row shell must render its row labels at
regular weight instead, to stay inside this phase's 2-weight budget. This intentionally breaks
exact visual parity with the pre-existing standalone card — that trade-off is accepted; the
pre-existing card itself is untouched by this phase and keeps its `w600` rows unchanged, and this
downgrade applies only to the new instance this phase creates. No third weight is introduced
anywhere in UI this phase touches.

## Color

Herculex is not a 60/30/10 marketing-surface app — it is a dark-first utility app with a
5-palette theme system (`AppColorTheme`: Classic Blue default). Mapped onto the template's
roles using `context.hx` tokens (resolve at runtime per active palette/brightness — do not
hardcode a hex, the values below are the Classic Blue Dark defaults for reference only):

| Role | Token | Reference hex (Classic Blue Dark) | Usage |
|------|-------|-----|-------|
| Dominant / background | `context.hx.background` / `surfaceContainerLowest` | `#091322` / `#111824` | Sheet and dialog backgrounds (via `HxSheet`/`AlertDialog`'s existing shells) |
| Secondary / surface | `context.hx.surfaceContainer` | `#161E2E` | Cards, banners' neutral state (e.g. `AiDayRationaleCard`'s background) |
| Accent | `context.hx.primary` | `#0A84FF` | Reserved for: sheet/dialog primary icon accents, the "Apply"/primary CTA button fill (existing `FilledButton`), the specialization info-icon, `AiDayRationaleCard`-style informational callouts. **Not** used for the new warning states below. |
| Warning (new semantic use this phase) | `context.hx.warning` | `#FF9F0A` | **Exclusively** for: (1) the timeline-shorter-than-recommended inline warning banner, (2) the unrealistic-kg-increase warning banner, (3) the volume-floor-below-minimum warning (both live-preview and Create-time). Matches `AiBriefRejectionBanner`'s existing `hx.warning` usage — same semantic family (advisory, non-blocking), reused rather than introducing a new color. |
| Destructive | `context.hx.danger` | `#FF453A` | Not used this phase — D-05 locks every new check in this phase to warning-only, never blocking/destructive. No destructive action is introduced. |

Accent reserved for: primary CTA fill/text (Apply, Create), the existing Dream-Physique-style
informational banner precedent, and any lift/sticking-point selection highlight state already
established by `_sheetOptionCard`'s `isSelected`/`isRecommended` styling (unchanged this
phase). Never use accent (`primary`) for a warning — all three new warning surfaces (D-08–D-11
timeline/kg-increase, D-04–D-07 volume floor) use `context.hx.warning`, matching D-05's explicit
"warning tone everywhere, no blocking language" decision and `VolumeVerdict`'s own existing
plain-language labels ("Light" / "On target" / "Hard" / "Over" — informational, not alarming).

**Visual hierarchy / focal point:** on the specialization modal and the Weeks picker, the
primary CTA (Apply/Create, accent-filled) and the sheet's existing content remain the focal
point. All three new warning banners (timeline, kg-increase, volume-floor) are secondary/
advisory — rendered below the existing content they relate to, at neutral `hx.warning`-tinted
surface elevation (not accent-filled, not placed above or over the CTA) — so a banner and the
CTA can both be visible at once without the banner competing with or visually outranking the
accent CTA.

## Copywriting Contract

### Sticking-point-aware copy (D-12)

Every lift's sticking-point dropdown and the post-Apply summary must reflect the lift-specific
mapping, not the generic squat/deadlift-only phrasing. `PrimaryLiftSpecialization.assistanceFocus`
already exists as the copy source for bench/OHP/pull-up (verified live in
`primary_lift_specialization.dart`) — the gap is that nothing in
`step_parameters_specialization.part.dart` or `step_parameters.part.dart` renders it. This
phase's UI work is to surface it, not invent new copy:

| Element | Copy |
|---------|------|
| Sticking-point dropdown label | "Where does the lift slow down?" (existing, unchanged — already lift-agnostic) |
| Sticking-point helper text (new, shown under the dropdown once a sticking point is selected) | Render `PrimaryLiftSpecialization(...).assistanceFocus` verbatim — e.g. for Bench Press + "Off the chest": "Chest volume and stable pressing technique are prioritised."; for Overhead Press + "Out of the bottom": "Strict pressing practice and shoulder control are prioritised."; for Pull-up + "From a dead hang": "Scapular control and vertical-pull volume are prioritised." Never truncated, never re-derived — the domain string is the UI string. |
| Pull-up-specific helper (existing, unchanged) | "For pull-ups, use 0 for bodyweight and enter added external load in kg when applicable." |

### Timeline realism warning (D-08–D-11)

Fires from the existing Weeks picker (`dialogs.part.dart:_showLengthPicker`) when
specialization is active and the tapped weeks value is less than
`PrimaryLiftSpecialization.recommendedWeeks()`.

| Element | Copy |
|---------|------|
| Inline warning heading | "Not enough time to progress safely" |
| Inline warning body | "{recommendedWeeks} weeks is a more realistic target for a {currentKg}→{targetKg} kg {liftLabel}. We've adjusted your block to {recommendedWeeks} weeks." — the exact auto-adjust behavior (D-09) must be named in the copy itself, since the picker closes with the corrected value already applied, not the user's tapped value. |
| Auto-adjust confirmation (transient, e.g. `SnackBar`, matching the existing `ScaffoldMessenger.of(context).showSnackBar` pattern already used for the current-load validation error in this same file) | "Block length adjusted to {recommendedWeeks} weeks to match your specialization target." |
| Unrealistic kg-increase warning heading (independent of D-08's timeline check, D-11) | "That's a big jump" |
| Unrealistic kg-increase warning body | "Adding {increaseKg} kg to your {liftLabel} is outside typical progress for {experienceLevel} lifters, even over {weeks} weeks. Consider a smaller target or a longer block." — exact numeric ceiling per experience tier is Claude's discretion per CONTEXT.md D-11 (left to research/planning); this copy template must stay generic enough to hold whatever threshold research lands on. |

Both warnings render via the `context.hx.warning`-toned banner pattern established by
`AiBriefRejectionBanner` (icon `Icons.warning_amber_rounded`, `hx.warning` heading/icon color,
`hx.warning.withValues(alpha: .08)` background fill) — reuse that visual shape (new widget or
extend `AiBriefRejectionBanner` itself; planning's call) rather than inventing a new banner
style. Never a blocking dialog, never a hard-stop `AlertDialog` — D-09 requires inline + auto-
adjust, not a modal interruption.

### Maintenance volume floor (D-04–D-07)

| Element | Copy |
|---------|------|
| Live-preview section heading (inside/near the specialization modal or Step Parameters, reusing `ProgramMuscleVolumeCard`'s existing title-row pattern) | "Weekly Volume per Muscle Group" (existing `ProgramMuscleVolumeCard` default title — reuse verbatim, do not rename) |
| Per-group low-volume flag (reusing `VolumeVerdict.low`'s existing labels, do not invent new ones) | Label: "Light" · Blurb: "Below the volume that usually drives progress" (both already defined in `volume_bands.dart` — render verbatim) |
| Create-time guardrail banner heading (new `ProgramGuardrailIssue`-shaped warning, `GuardrailSeverity.warning`) | "Some muscle groups will fall below maintenance volume" |
| Create-time guardrail banner body | "{muscleGroup} would get {weeklySets} sets/week with this specialization, below the {minimum}-set minimum for maintenance. You can still create this block." — must end by explicitly telling the user the action is not blocked (D-05: warning-only, everywhere), since `ProgramGuardrailIssue`'s existing blocking-severity siblings (Max Effort guardrails) do use stop-you-cold language and this must visually and textually read as different from those. |

### Primary CTA

| Element | Copy |
|---------|------|
| Specialization modal primary CTA | "Apply" (existing, unchanged) |
| No new CTA is introduced this phase | — all three new warnings are advisory banners/snackbars attached to existing flows (Weeks picker, Create button), not new screens with their own primary action |

Note: "Apply" is a generic single-word label without a noun (not, e.g., "Apply Specialization").
This was reconsidered during this revision and intentionally left as-is — it is pre-existing,
already-shipped copy on an existing `FilledButton` that this phase does not touch or extend; the
phase's own copy surface is limited to the new advisory banners/helper text above, not a rename
of an existing production CTA.

### Empty state

Not applicable — this phase adds no new empty-data view. The live volume-preview surface only
renders when specialization is active and the plan has assigned exercises; if
`ProgramVolumeBreakdown.isEmpty`, follow `ProgramMuscleVolumeCard`'s existing behavior
(`return const SizedBox.shrink()` — render nothing, no empty-state message needed since this is
a supplementary advisory surface, not a primary content area).

### Error state

| Element | Copy |
|---------|------|
| Existing current-load validation error (unchanged) | "Please enter your current load (kg)." (existing `SnackBar`, `step_parameters_specialization.part.dart:184`) |
| No new hard-error state is introduced | All three new checks this phase adds (D-05, D-09, D-11) are warnings, not errors — never block `_create()`, never show a validation-style rejection. This is a deliberate contrast with Phase 27's `AiBriefRejectionBanner` (which does block/reject) — reuse its visual shape, not its blocking semantics. |

### Destructive actions

None. This phase introduces no delete/remove/reset action. `SquatSpecialization` dead-code
removal (CONTEXT.md's "Dead code cleanup") is a code-only change with no UI surface — no
confirmation dialog needed.
