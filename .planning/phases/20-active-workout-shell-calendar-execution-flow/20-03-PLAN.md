<objective>
Turn the inline `_WorkoutPlanPreviewSheet` (private class nested in
`day_detail_sheet.dart`, opened as a sheet-on-sheet) into a standalone pushed
route `PlannedWorkoutPreviewView` that resolves its own data from a
`scheduleId` via a new Riverpod provider — matching `WorkoutHistoryView`'s
existing pattern (FLOW-02, D-09/D-10/D-11).

Purpose: give the preview a real back-stack entry instead of sheet-on-sheet
stacking, keep the "UI never touches drift directly" rule intact (the view
resolves via a provider, not pre-fetched `extra`), and pair the preview with a
`Start workout` CTA so users don't bounce back to `DayDetailSheet` to start.
`DayDetailSheet._viewWorkout` is updated to push this new route for every row
in this plan (status-based branching for done/in-progress lands in Plan
20-04) — this keeps the repository green at the end of this plan without
duplicating routing work.
Output: `AppRoutes.plannedWorkoutPreview` + `AppPaths.plannedWorkoutPreview`,
a `GoRoute` registration, `plannedWorkoutPreviewProvider`,
`PlannedWorkoutPreviewView`, and `_WorkoutPlanPreviewSheet`/
`formatPlannedExerciseSets` moved out of `day_detail_sheet.dart`.
</objective>
