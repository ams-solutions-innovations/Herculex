<objective>
Thread `row.id` through the calendar's session-tap callbacks so a day with
multiple sessions opens `DayDetailSheet` scrolled to and highlighting the
exact session the user tapped, instead of just the day (FLOW-03, D-04/D-05).
RESEARCH.md's Pitfall 3 found this bug exists at **two** call sites, not one:
`month_calendar.dart`'s `_SelectedDayList.SessionTile.onTap` (D-04's named
instance) and `week_board.dart`'s `onOpenSession(ScheduledWorkoutRow)` via
`training_blocks_view.dart._openDay` (an un-named second instance with the
identical shape) — this plan fixes both.

Purpose: resolve the ambiguity the blueprint calls out — a day with 2+
sessions currently gives no way to tell `DayDetailSheet` which one was
tapped.
Output: `DayDetailSheet(initialScheduleId:)`, `_openDay(..., {int?
initialScheduleId})` threaded from both `MonthCalendar` and `WeekBoard`
callers, and the first dedicated widget test for `month_calendar.dart`.

Discretion note (CONTEXT.md): this plan does NOT add `HxSheet`'s optional
`centerHeader` param. `DayDetailSheet`'s date header already renders with
`textAlign: TextAlign.center`, so the blueprint's centered-header goal is
already met without a new `HxSheet` param — adding one would be unused scope.
</objective>
