<objective>
Build the D-05 to D-08 UI: the estimate badge and the detail sheet, placed under the maintenance field.

Purpose: TDEE-04 requires every estimate to expose method, confidence, window and inputs and to be visibly distinct from a manual value. This is the only new screen surface in the phase.
Decision recorded here (open item 2): badge and sheet are PUBLIC files (`presentation/widgets/`, `presentation/sheets/`) rather than `part` files. Reasons: a `part` cannot carry its own imports (they would all go into the 2617-line library file), a `part` cannot be imported by Phase 29's weekly report which needs the same estimate-vs-target comparison (D-07), and ARCHITECTURE.md's filename-suffix rule places `*_sheet.dart` in `sheets/` and `*_badge.dart` in `widgets/`. CONTEXT D-05 only locks "inline badge that expands into a detail sheet" and the intent "do not grow the file in place", both satisfied. 28-UI-SPEC originally named private part files; it has been edited during plan revision so its "New components" table names the public files above (with a one-line note that this deviates from the earlier `part` idea because Phase 29 reuses them), and its behaviour, copy, tokens and sizes are followed unchanged, except for these minimal amendments already made in the spec: (a) the classifier's active calories, sleep and resting HR (which the classifier never uses) sit under a separate `Also recorded (not used in the estimate)` caption instead of inside WHAT WE USED; (b) the window line and the food-days denominator use `span_days + 1`, never the winning candidate window; (c) the comparison tiles' icons and the `set manually` caption placement are pinned.
Output: two public UI files, one small application provider, one few-line placement edit, widget tests.
</objective>
