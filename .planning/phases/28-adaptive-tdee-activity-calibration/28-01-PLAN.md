Implement `class ActivityClassifier` with `static ActivityClassification classify({required List<double> dailySteps, required double workoutsPerWeek, required double seedMultiplier, double? activeKcalPerDay, double? sleepHoursPerNight, double? restingHr})`. `dailySteps` is one value per day that has a steps sample in the last 14 days (the caller filters `HealthSamples.kind == 'steps'` and never passes `food_kcal`/`weight_kg` rows). Tunables live as `static const` on `ActivityClassifier` (the `DietPhaseCalculator` precedent), retunable in one place: `windowDays = 14`, `minStepDays = 3`, `fullWeightStepDays = 14`, `stepAnchors` as an ordered list of (steps, factor) pairs (3000, 1.20), (7500, 1.375), (10000, 1.55), (15000, 1.725), `trainingBonusPerWorkout = 0.02`, `trainingBonusCap = 0.10`, `minMultiplier = 1.15`, `maxMultiplier = 1.90`, `mediumConfidenceStepDays = 10`.

Algorithm: `stepDays = dailySteps.length`; below `minStepDays` return `ActivityClassification.unavailable`. `avgSteps` is the mean. Base factor: linear interpolation between the two surrounding anchors, clamped to the first/last anchor factor outside the range. `bonus = min(trainingBonusCap, trainingBonusPerWorkout * workoutsPerWeek)`. `dataWeight = min(1.0, stepDays / fullWeightStepDays)`. `multiplier = clamp(dataWeight * (base + bonus) + (1 - dataWeight) * seedMultiplier, minMultiplier, maxMultiplier)`. Confidence: medium when `stepDays >= mediumConfidenceStepDays`, else low; never high (RESEARCH #6). The output is a `double`, never an `ActivityLevel`, so the classifier does not reintroduce the four-bucket error this phase exists to remove (CONTEXT discretion, TDEE-02). Record in the class doc comment that the anchor coefficients are LOW-confidence assumption A7 and expected to be retuned after real usage.

`ActivityClassification` is a const class: `isAvailable`, `multiplier`, `confidence`, `stepDays`, `avgSteps`, `workoutsPerWeek`, `seedWeight` (`1 - dataWeight`), `activeKcalPerDay`, `sleepHoursPerNight`, `restingHr`; `static const unavailable` sentinel (isAvailable false, multiplier 0, confidence low, zeros); and `Map<String, Object?> toInputs()` per the behavior block. This map becomes `TdeeEstimateResult.inputs`, which the sheet shows individually per D-06 (for example "avg 9,200 steps/day, 3 logged workouts/week"). The seed value is the manual ActivityLevel multiplier; per D-14 a Profile reset changes only that seed input and nothing here discards history.

No `DateTime.now()`, no drift, no Flutter, no Riverpod.
