# Phase 28 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Flutter app (Riverpod, go_router, drift), not web. All "px" below are logical pixels (dp). All values are
> `design_system/` tokens, never literals. Sizes and colours resolve from `context.hx` (`HxColors`), `HxSpace`,
> `HxRadius`, `HxMotion` and `Theme.of(context).textTheme`.

**Scope of visible UI in this phase (small by design).** Phase 28 is mostly domain math. Only four surfaces change:

1. A new **TDEE estimate badge** under the "Maintenance calories" field in `TargetEditorView` (D-05, D-08).
2. A new **TDEE detail sheet** opened by tapping that badge (D-05, D-06, D-07).
3. **Copy and confirm behaviour** on the existing Profile "Activity Level" picker (D-13, D-14, D-15).
4. **Copy** on the existing onboarding activity step (D-12).

Explicitly **not** in this phase: the weekly-report accept/dismiss prompt (D-10, Phase 29), any "material shift" UI (D-11),
any new screen or route, any AI surface.

## Spacing Scale

Declared values use the project's `HxSpace` scale (every value is a multiple of 4). Use the constants, never numeric literals.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| `HxSpace.x1` | 4px | Icon-to-label gap inside badge; badge vertical padding |
| `HxSpace.x2` | 8px | Gap between maintenance field and badge row; gap between badge row and phase subtitle; gap between stacked info rows |
| `HxSpace.x3` | 12px | Badge horizontal padding; gap between the two comparison tiles |
| `HxSpace.x4` | 16px | Sheet section gaps; inner padding of the "What we used" card |
| `HxSpace.x5` | 20px | Sheet side padding (HxSheet default, unchanged) |
| `HxSpace.x6` | 24px | Gap between sheet sections |
| `HxSpace.x8` | 32px | Onboarding: gap between subtitle and first activity tile (existing value retained) |

Exceptions:

- **Badge touch target is 44 x 44 minimum** even though the visible pill is about 24px tall. Wrap the pill in a
  `ConstrainedBox(minHeight: 44)` with the pill vertically centred, so the hit area meets the platform minimum without
  inflating the visual. 44 is a multiple of 4.
- **Do not use `HxTextPill`** for the badge: its vertical padding is `HxSpace.x1 + 2` (6px), off-scale. Use `HxPill` with an
  explicit `padding: EdgeInsets.symmetric(horizontal: HxSpace.x3, vertical: HxSpace.x1)`.
- Badge icon is **16px** (not the 14px used by `SyncStatusBadge`) to stay on the 4px grid.
- Inherited from `HxSheet` and left untouched: 40 x 4 grab handle, 10px top gap, `HxSpace.x5` side padding.

Placement inside `TargetEditorView` (replaces the current single 6px gap after the maintenance `_NumField`):

```
_NumField(Maintenance calories)
SizedBox(height: HxSpace.x2)
Align(centerLeft) -> _TdeeBadge            // min hit height 44
SizedBox(height: HxSpace.x2)
Text(_phase.subtitle)                      // existing, unchanged
```

## Typography

Four sizes, two weights for all **new text authored in this phase**. Everything comes from the existing `textTheme`
ramp; no new type styles are introduced. Any kcal or count figure adds `fontFeatures: [FontFeature.tabularFigures()]` so
digits do not jitter when an estimate changes (matches `AppTheme._tabular`).

| Role | Size | Weight | Line Height | Used for |
|------|------|--------|-------------|----------|
| Body | 15px (`bodyMedium`) | 400 regular; 700 for row values | 1.5 | Sheet descriptions, "What we used" labels and values, dialog body, onboarding subtitle |
| Label | 12px (`labelSmall`) | 700 (badge, section caps) / 400 (captions, footnote) | 1.3 | Badge text, sheet section headers (uppercase, `letterSpacing: 1.0`), Profile caption, footnote |
| Heading | 17px (`titleMedium`) | 700 | 1.2 | Sheet title (rendered by `HxSheet`) |
| Display | 22px (`titleLarge`) | 700 | 1.2 | Comparison figures (rendered by `HxStatTile`) |

Weights: **400 and 700 only** for text this phase writes. Shared components keep their own internal weights and are exempt
(`HxStatTile` caption is 500 via `labelSmall`; `HxSheet` title is 700). The existing onboarding heading
(`displayMedium`, 28px) is unchanged apart from its words.

Copy never truncates with ellipsis in the badge or sheet rows. At large text scale the badge grows to two lines
(`softWrap: true`, `maxLines: 2`); confidence wording is safety-relevant and must stay readable.

## Color

All colours are `HxColors` tokens, so all five app themes (Classic Blue, Sirious Black, Vivid Green, Sunny Yellow, Pinky)
and both brightnesses work with no per-theme code. Hex values below are the Classic Blue default, for reference only.

| Role | Token | Classic Blue dark / light | Usage in this phase |
|------|-------|---------------------------|---------------------|
| Dominant (60%) | `hx.background` | `#091322` / `#E4EFFC` | Page behind the editor (unchanged) |
| Secondary (30%) | `hx.surfaceContainer` | `#161E2E` / `#FFFFFF` | Sheet shell (via `HxSheet`) |
| Secondary (30%) | `hx.surfaceContainerLowest` | `#111824` / `#F5F9FF` | Badge idle fill base, nested `HxCard` inside the sheet |
| Accent (10%) | state colour, see table below | see table | Badge icon, border and 15% tint; state icon in sheet header; estimate tile accent |
| Destructive | `hx.danger` | `#FF453A` / `#C7261C` | **Not used in this phase** |

### Badge state colours

Accent colours **only** the icon, the border and the 15% alpha tint (the `HxPill` `selected: true` treatment, held
permanently so it reads as a status chip, not a toggle). **Badge text is always `hx.onSurface`**, which guarantees the 4.5:1
contrast floor in every theme without per-theme checks.

| State | Trigger | Accent token | Icon | Rationale |
|-------|---------|--------------|------|-----------|
| Measured | Observed-expenditure estimate, fresh | `hx.success` | `Icons.insights_rounded` | Backed by the user's own logged data |
| Measured, aging | Observed estimate inside the D-04 grace period | `hx.warning` | `Icons.insights_rounded` | Needs attention, not an error |
| Classified | Activity-classifier fallback | `hx.primary` | `Icons.directions_run_rounded` | Normal derived state, deliberately not amber or red |
| Calibrating | Cold start / no estimate row yet / read failure | `hx.onSurfaceVariant` | `Icons.hourglass_top_rounded` | Neutral placeholder; D-08 says never an error look |

Accent reserved for: (1) the badge icon, border and tint; (2) the state icon beside the method line at the top of the detail
sheet; (3) the accent of the "Maintenance estimate" `HxStatTile` in the sheet; (4) the already-existing selected
ActivityLevel tile in Profile (unchanged).

Accent is **not** used for: sheet section headers, chevrons, dividers, row values, dialog buttons, or the "Your saved target"
tile (that tile takes neutral `hx.onSurfaceVariant`).

No red/green judgement on the comparison in the sheet. A gap between the saved target and the estimate is not good or bad.

## Copywriting Contract

Strings marked (locked) come verbatim from CONTEXT.md decisions. Strings marked (proposed) satisfy the decision's intent
and CONTEXT.md's "illustrative, not final strings" note; the planner may adjust wording but not meaning.

### Badge label, format `{Method} · {Confidence}`

| State | Copy | Source |
|-------|------|--------|
| Measured, high | `Measured · High confidence` | (locked) D-05 |
| Measured, medium | `Measured · Medium confidence` | (proposed) |
| Measured, aging | `Measured · Aging estimate` | (proposed) D-04 "clearly labelled aging/stale" |
| Classified, medium | `Classified · Medium confidence` | (locked) D-05 |
| Classified, low | `Classified · Low confidence` | (proposed) |
| Calibrating | `Calibrating — using onboarding estimate` | (locked) D-08 |

Rules: Classified never shows "High confidence" (RESEARCH.md #6). Badge is never blank and never shows an error string.

### Detail sheet

| Element | Copy |
|---------|------|
| Sheet title | `Maintenance estimate` |
| Method line: Measured | `Worked out from what you ate and how your weight trended.` |
| Method line: Classified | `Worked out from your daily activity and training.` |
| Method line: Aging | `Measured from your logs {N} days ago. Log again to refresh it.` |
| Method line: Calibrating | `Using the activity level you chose at setup until there is enough data to measure.` |
| Section: window | `WINDOW` then `Based on the last {N} days` and `Updated {relative date}` |
| Section: inputs | `WHAT WE USED` |
| Comparison tile labels | `YOUR SAVED TARGET` (caption `set manually`) and `MAINTENANCE ESTIMATE` |
| Comparison footnote | `Your saved target includes any cut or bulk adjustment, so it can sit above or below maintenance on purpose.` |
| Trust footnote | `This is an estimate, not a medical measurement. It never changes a target you set yourself.` |

Input rows (D-06). Render only rows that have data; never render a "-" or "N/A" row.

| Method | Rows (label : value) |
|--------|----------------------|
| Measured / Aging | `Average intake : 2,310 kcal/day`, `Days with food logged : 12 of 14`, `Weight trend : -0.4 kg`, `Weigh-ins : 6`; Aging adds `Last measured : 9 days ago` |
| Classified | `Average steps : 9,200/day`, `Logged workouts : 3/week`, `Active calories : {X} kcal/day`, `Sleep : 7.4 h/night`, `Activity factor : 1.55` |
| Calibrating | `Onboarding activity level : Lightly Active`, `Activity factor : 1.375` |

Numbers above are format examples. Group thousands with `NumberFormat` as the rest of the app does; unit suffixes as shown.
Frozen snapshot from the estimate's `inputsJson`, not a live re-query (RESEARCH.md open question 3; recommended reading of D-06).

### Comparison (D-07)

- Saved manual target exists: two `HxStatTile`s side by side, then the comparison footnote.
- No saved target: one full-width `MAINTENANCE ESTIMATE` tile, no footnote, no empty placeholder tile.
- Do **not** print a delta number or arrow between them (target is phase-adjusted, estimate is maintenance; a delta would mislead).

### Profile "Activity Level" (D-13, D-14, D-15)

| Element | Copy |
|---------|------|
| Section header | `Activity Level` (unchanged) |
| Caption, still Calibrating | `Your starting estimate. We'll refine it automatically as you log.` |
| Caption, calibrated | `Manual reset. Use this only if your routine changed a lot. It reseeds the estimate and keeps your history.` |
| Confirm dialog title (calibrated only) | `Reset activity level?` |
| Confirm dialog body | `This becomes your new starting point. It won't erase your calibration history.` |
| Confirm dialog actions | `Cancel` and `Reset` |
| Snackbar after reset, user currently Measured (D-15) | `Saved. Your estimate stays measured from your logs.` |
| Snackbar after reset, Classified / Aging / Calibrating (D-14) | `Saved. We'll use this as the starting point at the next recalibration.` |

While Calibrating, tapping a tile saves immediately exactly as today (no dialog), because the pick is the seed.

### Onboarding (D-12)

| Element | Copy |
|---------|------|
| Heading (replaces `What is your activity level?`) | `How active are you right now?` |
| New subtitle under heading | `This is just a starting point. We'll refine it automatically as you log.` |

Layout: heading, `HxSpace.x2` gap, subtitle (Body, `hx.onSurfaceVariant`), then the existing 32px gap to the first tile.

### Required contract fields

| Element | Copy |
|---------|------|
| Primary CTA | `Reset` (confirm action of the Profile reset dialog). The badge itself is the discovery affordance for the sheet and carries no button label. |
| Empty state heading | Badge reads `Calibrating — using onboarding estimate` (the cold-start state doubles as this feature's empty state) |
| Empty state body | Sheet method line for Calibrating, plus the input row `Onboarding activity level`. Adds: `Log food and your weight for about two weeks and this switches to a measured number automatically.` (proposed) |
| Error state | No red UI, no error string. If the estimate read or compute fails, render the Calibrating state with identical copy and report the failure through the existing error-reporting path. Follows D-08 "never blank, never an error state". |
| Destructive confirmation | None in this phase. The Profile reset is non-destructive by design (D-14: reseeds only, history retained), so it uses a standard confirm `AlertDialog`, not `hx.danger` styling. |

## Interaction and State Contract

### Badge

| Behaviour | Spec |
|-----------|------|
| Tap | `HxPill(onTap:)` fires `Haptics.selection()` (built in), then `HxSheet.show(context, builder: ...)` |
| Trailing affordance | `Icons.chevron_right_rounded`, 16px, `hx.onSurfaceVariant`, so the tap-through is discoverable |
| State change | Wrap in `AnimatedSwitcher(duration: HxMotion.base)` so a recalibration does not snap |
| Loading (first frame of the estimate stream) | Reserve the row height (`SizedBox(height: 44)`), draw nothing, fade in with `HxMotion.base`. No spinner: it is a local drift read. This is layout-stability only, not the data-state "blank" that D-08 forbids. |
| Editing the field | Badge always describes the **estimate**, never the text the user is typing. Changing `_maintenanceKcal` does not change the badge. |
| Semantics | `Semantics(button: true, label: 'Maintenance estimate: {method}, {confidence}. Double tap for details.')` |

### Detail sheet

- `HxSheet(title: 'Maintenance estimate', scrollable: true, initialSize: 0.6, maxSize: 0.92)`. **Do not pass `subtitle`**
  (it would add a 13px size); the method line goes in the body at Body size.
- Read-only. **No Done button, no accept/dismiss.** Dismissal is swipe-down or scrim tap, as with every other `HxSheet`.
  Accept/dismiss (D-10) belongs to Phase 29 and must not be prototyped here.
- Section order, top to bottom: status row (state icon + `{Method} · {Confidence}` at Body/700, then the method line at
  Body/400 in `hx.onSurfaceVariant`) -> comparison tile(s) -> `WINDOW` -> `WHAT WE USED` in an `HxCard`
  (`padding: EdgeInsets.all(HxSpace.x4)`, `radius: HxRadius.md`) -> trust footnote.
- Section headers: Label style, uppercase, `letterSpacing: 1.0`, `hx.secondary` (same as `HxStatTile` captions and the existing
  `_SectionTitle` convention in this view).
- Input rows: label left (Body/400, `hx.onSurfaceVariant`), value right (Body/700, `hx.onSurface`, tabular figures),
  `HxSpace.x2` between rows, no dividers.
- Comparison tiles: `Row` of two `Expanded` `HxStatTile`s with `HxSpace.x3` between. "Your saved target" uses
  `accent: hx.onSurfaceVariant`; "Maintenance estimate" uses the state accent from the badge table.
- Source of "saved target": the resolved saved `NutritionTargetData` via `nutritionTargetsProvider` / `TargetResolver` for
  today's scope, not the in-progress editor field.

### Profile reset

- Calibrated state only: selecting a different tile shows the confirm `AlertDialog` (theme `dialogTheme`, no custom styling);
  `Cancel` leaves `_activityLevel` unchanged; `Reset` saves via the existing `_onFieldChanged()` path, then shows the snackbar
  variant that matches the current method (D-14 vs D-15).
- Never clears or hides prior `TdeeEstimates` history (D-14).

### Motion

Use `HxMotion` only: `base` (200ms) for the badge state switch and load fade; sheet uses the standard modal transition.
No custom curves. No looping animation on the Calibrating state (a pulsing hourglass would read as "loading/error").

### Accessibility

- Text contrast is guaranteed by rendering badge text in `hx.onSurface`; accent only decorates icon/border/tint.
- 44 x 44 minimum touch target on the badge.
- Colour is never the sole signal: every state has a distinct icon plus distinct words in the label.
- Layout survives 2x text scale (badge wraps to two lines, sheet scrolls, no fixed-height rows).
