<objective>
Build the sending half: the policy that decides whether a local change is shared, and the sender that
mints slot identity, applies locally, and publishes only when it should.

Purpose: BUD-03's sending side. The requirement most likely to break under refactor is that a "only
me" change never reaches the partner — so this plan makes that structural. The scope branch is control
flow in this module, and `BuddyEventPublisher.append` has no scope parameter to pass it to even if
someone tried.

Output: two files under a NEW `lib/features/buddy/application/` directory — deliberately outside the
transport module the scope-boundary gate polices — plus the sender test suite.
</objective>

  <action>
    Create `lib/features/buddy/application/buddy_choreography_sender.dart` implementing the class in
    the interfaces block.

    The structural rule this plan exists to enforce: the scope check is an `if` in this file and
    nothing else. Write it as an early return — when `scope` is `BuddyScope.mine`, perform the local
    mutation and return before the publisher is in scope at all. Do not pass scope onward, do not put
    it in a payload map, do not log it into the event.

    Slot identity: `addExercise` mints a slotId via the injected `newSlotId` (default `Uuid().v4()`).
    The minting device owns the id; every later event about that exercise addresses it by slotId, which
    is what makes reorder and remove idempotent and order-independent (research Pitfall 4).

    Rollback: apply the local mutation first, then publish. If `append` throws, undo the local mutation
    in the same call — remove the just-added exercise, restore the previous ordering, or re-add the
    removed one — and rethrow. This is why `FakeBuddyPublisher.failWith` exists. Do NOT swallow the
    error and leave the devices divergent.

    References: build every `BuddyExerciseRef` from `SyncIdResolver.resolveCatalogueRefForPush`, which
    returns a uuid for a custom row and a natural key for a seeded one. Task 1's policy means the
    custom case should not reach here with scope both, but construct the ref correctly regardless
    rather than assuming.
  </action>
