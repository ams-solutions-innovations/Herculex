  <behavior>
    - A scripted session — host adds three exercises with scope both, both log different sets on each, host adds one with scope mine, guest replaces one with scope both — ends with both devices holding the same shared exercise list

    - Device A's scope-mine exercise exists on A and does not exist on B

    - After a propagated remove of an exercise on which B has logged sets, B still holds those sets and A does not
    - Neither device holds a `BuddySessionsLocal` row referencing the other's local workout session id

    `BuddyChoreographyApplier` on the receiving side, connected by a shared in-memory log standing in
    for the server. Hand-constructing the event list would test the assertions rather than the system —
    the point is that the production sender produces events the production applier turns into isolated
    state.

    Assert isolation positively and negatively: not just that B's set count is what B logged, but that
    no row in B's `SetEntries` carries the distinctive weight and rep values only A logged. Give A and
    B deliberately distinguishable set values so the assertion can be exact.

    Assert the session-identity separation too: two `WorkoutSessions` rows, two `sessionUuid`s, one
