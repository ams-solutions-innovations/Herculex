Build `GppProgramPlanner`, the pure domain service for the GPP conditioning day content, resolving two CONTEXT.md discretion items explicitly (not silently defaulting either):

1. **GPP day shape**: standalone 3rd training day, matching the already-shipped `SplitType.fullBodyAbGpp` skeleton (`['Full Body A', 'Full Body B', 'GPP']`, `defaultDaysPerWeek: 3`) and `block_builder_view.dart`'s existing `TrainingStyle.fullBody2xGpp -> SplitType.fullBodyAbGpp` wiring — this is the lower-new-architecture-work path per RESEARCH.md's own recommendation, and matches what the split skeleton and UI copy already assume.

This plan's job is to (a) keep every GPP-authored slot off `SlotRole.main`/`supplemental` so that existing guard stays closed, and (b) add the explicit regression test RESEARCH.md's Validation Architecture flagged as currently missing.

GPP pool size (4 exercises: burpee, rowing-erg, air-bike, stationary-bike) ships as-is this phase — RESEARCH.md's own recommendation is to NOT widen eligibility to the 17-exercise `crossfit` pool (which contains barbell/Olympic/gymnastics work, unsafe for a "no 8x3, no DE" day) and to explicitly flag the 4-exercise thinness as a known, documented limitation rather than either silently expanding scope or silently ignoring it.

Purpose: Today, `smart_program_planner.dart`'s `_needsFor` gives a GPP-labeled day exactly `[_SlotNeed(null, null, SlotRole.conditioning)]` with no segment tag and no test proving the DE-exclusion holds. This plan documents and hardens that existing behavior into a tested, segment-tagged, explicit domain service Plan 21-06 wires in.
Output: `gpp_program_planner.dart`'s `segmentNeedsFor`; a passing regression test for the DE guard.
