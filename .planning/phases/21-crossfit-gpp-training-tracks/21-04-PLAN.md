<objective>
Build `CrossfitProgramPlanner`, the pure domain service that assembles a CrossFit training day's ordered segment blueprint (D-01/D-02: warmup, skill, strength, metcon, cooldown — skill and strength are two separate segments, not one segment with two flavors). This is genuinely additive: it produces `CrossfitSlotNeed` descriptors (pattern/muscle/role hints, exactly the shape `smart_program_planner.dart`'s existing private `_SlotNeed` already uses for every other split, per D-01's naming note) tagged with `SessionSegment` — it does NOT query the exercise catalog or the database itself. Candidate exercise selection for each need still runs through `smart_program_planner.dart`'s existing, unmodified `_createStableSlots` pipeline (equipment/style/experience/prerequisites filtering, `ExerciseProgrammingEligibility.allows` + `.verifyPrerequisites`), which already correctly gates CrossFit movements once 21-03's metadata fixes land — this plan does not duplicate that gating.

ROADMAP.md's Phase 21 success line names all three metcon formats explicitly ("AMRAP, EMOM, and For Time formats preserve time caps") — the metcon segment's format must therefore be genuinely selectable across all three, not hardcoded to one. This plan rotates format deterministically by an input `variationSeed` (the calling day's position — Plan 21-06 passes the program day's `orderIndex` or week index), so a multi-week CrossFit program exercises all three formats across its weeks rather than only ever producing AMRAP content.

Purpose: Today, `smart_program_planner.dart`'s `_needsFor` gives every CrossFit day exactly two bare `SlotRole.conditioning` slots (`trainingStyle.isConditioningFirst` branch, lines 1227-1231) — a "conservative conditioning-first skeleton" placeholder. This plan builds the real segment-aware replacement that Plan 21-06 will wire in.
Output: `crossfit_program_planner.dart`'s `segmentNeedsFor`.
</objective>
