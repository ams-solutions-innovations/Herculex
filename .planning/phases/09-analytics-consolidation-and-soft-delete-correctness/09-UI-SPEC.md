# Phase 9 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Note on scope:** This project is Flutter (Material, `lib/theme/app_theme.dart` + `lib/theme/colors.dart`), not a shadcn/web stack — the template's shadcn-specific fields below are marked "not applicable" rather than force-fit. Per `09-CONTEXT.md`, this phase introduces **zero new visual design**. The only UI change is a deletion: `_RecoveryCard` (and its instantiation) is removed from `lib/features/analytics/presentation/insights_view.dart`; `RecoveryDetailCard` becomes the sole recovery view. Every other card on the Insights screen (`CnsTrendCard`, `_BalanceCard`, `_TonnageCard`, `_OneRmCard`, `_SleepVsRpeCard`, `_HrVsTonnageCard`) is visually unchanged — only their underlying data source changes (soft-delete-filtered, effective-load-aware), per CONTEXT.md decision D-03 (ship silently, no banner).

This contract exists to lock that boundary, not to introduce new tokens.

## Visual Hierarchy

Unchanged by this phase. `RecoveryDetailCard` (the v3, 19-muscle-group recovery card) remains the first card on the Insights screen and the primary visual focal point — it simply moves up one slot to occupy the position `_RecoveryCard` previously held, with no change to its own layout, size, or styling. All other cards keep their existing order and hierarchy.

| Role | Value | Usage |
