Layering decisions made here (planner, per RESEARCH Architecture Patterns and the domain-purity rule in CLAUDE.md):
- `PhaseEligibility` lives in `lib/features/nutrition/domain/` because it is expressed purely in `DietPhase` terms. Physique domain imports nutrition domain; nutrition domain never imports physique. This avoids a nutrition <-> physique cycle.
- `lib/features/physique/domain/**` must import no Flutter and nothing from any `data/` folder. RESEARCH flags that the existing recommender imports `data/dream_physique_summary_repository.dart`; new files declare their own plain input types instead.
- First-phase equality with the old recommender is guaranteed structurally: the decision rule is extracted into `PhysiqueDirectionRule` and the old `DreamPhysiqueNutritionRecommender.recommend` delegates to it (existing tests stay green and are the regression proof).

Open Question 1 default (RESEARCH, recorded here as the plan's decision): minors and unknown age gate the roadmap AND the manual editor; low confidence gates roadmap generation and the deep-link preset phase only. Hence two public entry points: `PhysiqueGuardrails.ageEligibility` (editor) and `PhysiqueGuardrails.evaluate` (roadmap).

Unknown confidence: per D-06 the restriction triggers on a "low label or wide band". An absent label (`unknown`) is NOT restricted while `PhysiqueTuning.unknownConfidenceRestricts` is false (RESEARCH Pitfall 7: flipping it before the edge function that returns the new fields is deployed would restrict every existing user). Plan 17 documents the post-deploy flip.
