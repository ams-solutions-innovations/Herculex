# Phase 23 — UI Design Contract

> Visual and interaction contract for Phase 23: Persistent Dream Physique & Multi-Phase Nutrition. Generated by gsd-ui-researcher, verified by gsd-ui-checker. Flutter app: the web template sections (shadcn, CSS, registries) are adapted to design tokens, `ThemeExtension` and the existing `design_system/components`.

Sources: decisions D-01..D-13 from `23-CONTEXT.md`; Open Questions and defaults from `23-RESEARCH.md`; PHYS-01..08 from `REQUIREMENTS.md`; token and component inventory read from `lib/design_system/` on 2026-10-02; track rules from `CLAUDE.md` and `docs/ui-rework/ROADMAP.md`.

## Hard rules for this phase (checker and auditor enforce)

1. **Tokens only.** Colours come from `context.hx.*` (`HxColors`). Do NOT import or reference `AppColors` (`design_system/theme/colors.dart`; UI-rework Phase 9 deletes it). No `Color(0x...)`, no `Colors.white/black` (the one exception: none in this phase). Tints are `token.withValues(alpha: 0.14)`.
2. **No new design-system tokens, no new `design_system/` files.** Everything new is feature-local under `lib/features/physique/presentation/`. `design_system/` never imports `features/`.
3. **Frosted, not glow.** No coloured shadow, halo, bloom or glow on any new surface (cards, chips, CTAs, the verdict chip, chart lines). Glass appears only where `HxScreenShell`/`HxSheet` already supply it.
4. **No percentage on the verdict.** The PHYS-07 verdict UI shows chip + range bar + one-line reason + a confidence word (Low / Medium / High). No `%` character may be rendered inside the verdict card, its semantics label, or its tooltip. (Body-fat targets and goal BF values elsewhere on the screen are measurements, not verdicts, and may show `%`.)
5. **Never an automatic calorie write.** Every calorie action is a button that pushes `AppRoutes.nutritionTargets` with `extra: DietPhase`.
6. **No shaming, no negative gamification.** "Off track" uses `warning`, never `danger`. `danger` is reserved for destructive confirmations.
7. **File limits.** Every new file at most 600 lines. Do not grow `dream_physique_view.dart` (1780), `dream_physique_priorities_view.dart` (608) or `nutrition_targets_view.dart` (2618) beyond the call-site edits listed under "Edits to existing surfaces".

### S1 layout (top to bottom, single scroll column, gutter `HxSpace.x5`, gap between cards `HxSpace.x4`)

1. **Goal header card** (`HxCard`, no accent): goal style (Heading), line "Target {n}% body fat · started {date}" (Body), If the goal is archived (opened from S5) show neutral pill "Archived" and hide every action.
2. **Restriction notice** (only when `PhaseEligibility` restricts): inline tinted block, see Guardrail UI.
3. **Active phase card** (`HxCard`, `accent: domainNutrition`), PHYS-05:
   - Row: phase icon chip + phase name in Display (24) + right-aligned Label "Phase {i} of {n}".
   - Time line: "Week {w} of {planned}" (Body) with a determinate progress bar (track `surfaceVariant`, fill `domainNutrition`, 8 high, `HxRadius.pillAll`).
   - Tempo line (Body, `onSurfaceVariant`): "About {x.x} kg per week" (cut/bulk/maingain) or "Hold your weight steady" (maintain) or "Weight stays flat while body composition shifts" (recomp). Never a kcal figure here; kcal lives in the nutrition editor.
   - "Exit when" list: one row per criterion, check icon `Icons.radio_button_unchecked_rounded` (met: `Icons.check_circle_rounded` in `success`), copy per Copywriting.
   - **Advance prompt** (D-02), visible only when criteria met or duration elapsed: tinted block (`domainNutrition` alpha 0.14, `HxRadius.mdAll`, padding `HxSpace.x4`) with title "Ready for the next phase?", Body line naming the next phase, `FilledButton` "Move to {Phase}" and `TextButton` "Not yet". "Not yet" postpones the prompt 7 days (default; planner may tune) with SnackBar "We'll ask again in a week."
   - Footer row: `TextButton` "Edit roadmap" (opens S2) and `TextButton` with trailing `Icons.arrow_forward_rounded` "Review nutrition targets" (deep link, never a write).
4. **Roadmap timeline card** (`HxCard`): vertical timeline, one row per phase: node (16 diameter), phase label (Body 15 / w600 rather than Heading), duration "{n} weeks", status Label ("Done", "Current", "Up next"). Done node: filled `domainNutrition` with check; Current node: 16 ring in `primary` (accent) with 8 filled core; Up next: 2px `outlineVariant` ring. Connector 2px `outlineVariant`. Vertical (not horizontal) so text scale 200% and 6+ phases never truncate.
5. **Check-in card** (`HxCard`, no accent): header row "Check-in" (Heading) + neutral `HxTextPill` "Herculex AI"; body = latest verdict block (see Verdict block) or empty state; footer = check-in button with cap state; below, a thumbnail strip of the latest 3 check-ins (72 x 96, `HxRadius.smAll`) and `TextButton` "See all check-ins" (opens S4).
6. **Range control**: `HxTopTabs` labels `['1M', '3M', 'All']`, drives all three charts below. Default `3M`; if the goal is under 30 days old default `All`. Sticky is NOT required.
7. **Chart cards** (three stacked `HxCard`s, chart area height 200, see Charts): Bodyweight, Strength, Training level.
8. **Past goals row** (`HxCard` with `onTap`, trailing chevron): "Past goals" + count; opens S5. Hidden when none.

### Verdict block (PHYS-07, D-11)

- **Chip** (`HxPill` look, non-interactive, `HxRadius.pillAll`, padding `HxSpace.x2`/`HxSpace.x4`): icon + label in Label (13 / w600), label colour `onSurface`, icon and 1px border in the state colour, fill = state colour alpha 0.14. State mapping (colour is never the only signal: icon and word always present):

  | State | Label | Icon | Colour token |
  |-------|-------|------|--------------|
  | on track | On track | `Icons.trending_up_rounded` | `success` |
  | off track | Off track | `Icons.trending_flat_rounded` | `warning` |
  | inconclusive | Inconclusive | `Icons.help_outline_rounded` | `secondary` |

- **Confidence range bar** (custom `CustomPainter`/`Container` stack, height 12 = `HxSpace.x3`, full width): track `surfaceVariant`; a 2px centre tick in `outline` marks "no change vs baseline"; the filled segment spans the returned band `[lo, hi]` mapped from `[-1, +1]`, fill = state colour, `HxRadius.pillAll`, minimum drawn width 12 so a narrow band stays visible. End captions under the bar, Label 13 / w400 `secondary`: left "Away from goal", right "Toward goal". A wide segment IS the uncertainty message; no numbers on or near the bar.
- **Reason line**: one sentence, Body 15 / w400, `onSurface`, one sentence, wraps freely, no truncation. Below it a Label caption "Confidence: Low | Medium | High" in `secondary`. For `low`/`unknown` confidence add the hint "Log measurements to refine this." as `TextButton` to `AppRoutes.measurements`.
- **Footnote** (Label 13 / w400, `secondary`, always shown): "An estimate from your photos, not a measurement."
- **Actions beneath**: if verdict is off track or inconclusive, `TextButton` "Review nutrition targets" (deep link). On track shows no calorie action.
- Animation: band segment grows from the centre tick over `HxMotion.slow` with `HxMotion.emphasized` on first appearance only. Respect `MediaQuery.disableAnimations` (render final state instantly).
- Semantics label (no `%`): "Check-in verdict: {On track}. Direction estimate leans {toward|away from} your goal, {low|medium|high} confidence. {reason}".

### Charts (PHYS-08, D-12)

Shared: `fl_chart` `LineChart`, height 200, card padding `HxSpace.x5`, title row (Heading 17 / w600) + latest value in Display 24 / w600 when a value exists. Grid: horizontal lines only, `outlineVariant` alpha 0.5, no vertical grid, no border. Axis tick text Label 13 / w400 `secondary`; left axis max 4 ticks, bottom axis max 4 labels (date, `MMM d`). Line width 2.5, curved, no dots except the final point (radius 4, filled with the series colour, 2px `surfaceContainerLowest` ring). Touch tooltip: fill `surfaceContainer`, text `onSurface` Body 15 / w600, no shadow. Phase boundaries: dashed vertical `ExtraLinesData` in `outline`, 1px, no labels. Chart animation duration `HxMotion.slow`, `Duration.zero` when `disableAnimations`. A legend row (Label, 8 gap) sits under each chart. Every chart card carries a one-line text summary under the legend (Body 15 / w400, `onSurfaceVariant`), e.g. "Down 1.2 kg over 3 months." This is the screen-reader and low-vision equivalent of the chart (`Semantics(label: summary, excludeSemantics: true)` around the plot).

| Chart | Series | Colour tokens | Notes |
|-------|--------|---------------|-------|
| Bodyweight | `TrendSeries` smoothed line; raw weigh-ins as faint dots; phase-target band | line `onSurface`; raw dots `secondary` radius 2; band `domainNutrition` alpha 0.14 (`RangeAnnotations`, or `BetweenBarsData` when the band moves per week) | Legend: "Trend", "Target range" |
| Strength | e1RM (Epley/Brzycki avg) for one canonical lift at a time | line `domainTraining` | Lift selector above the plot: `HxPill` row (horizontally scrollable) over the `PrimaryLift` set (Squat, Deadlift, Bench, Overhead press, Pull-up); default = lift with the most recent data; lifts with no data in range are shown disabled (`onTap: null`, text `tertiary`). Unit kg |
| Training level | Step line over three levels from `ExperienceLevel` (Novice / Intermediate / Advanced) | line `domainTraining` | Y axis shows level names (Label), not numbers. Caption always visible: "Based on your training history, not your XP rank." |

Empty/sparse: fewer than 2 points in the selected range replaces the plot with the empty-state copy in a centred 200-high block (icon 32 in `tertiary`, Body 15 `onSurfaceVariant`).

## Guardrail UI (PHYS-04, D-05, D-06)

Restriction notice component (`RestrictionNotice`): tinted block (`warning` alpha 0.14 fill, `HxRadius.mdAll`, padding `HxSpace.x4`), leading `Icons.health_and_safety_outlined` icon, 20px, in `warning`, Body text `onSurface`, optional trailing `TextButton`. It explains, it does not blame, and it always offers the safe next step.

Used in three places, same component, different copy (see Copywriting):
1. S1 above the active phase card.
2. S2 roadmap editor: restricted phase types appear in the "Add phase" picker as disabled `HxPill`s (`onTap: null`) with the reason in the notice; they are NOT silently removed.
3. S8 nutrition targets editor: restricted `DietPhase` chips are disabled with the same notice. Missing age gets the "Add age in Profile" action (deep link to `AppRoutes.profile`), never a silent removal (RESEARCH Pitfall 12).

Low-confidence restriction applies to roadmap generation and the deep-link preset phase only (RESEARCH Open Question 1 default); the manual editor is gated for minors/unknown age only.

## Interaction Contract

### Roadmap editor (S2, D-01)

- `HxSheet` title "Your roadmap", subtitle "Reorder, resize or remove phases. Nothing changes your calories until you set targets." `initialSize 0.85`, `pinnedBottom` holds `FilledButton` "Accept roadmap" (full width). When editing an already-accepted roadmap the CTA reads "Save roadmap".
- Body: `ReorderableListView` of phase rows inside the sheet. Row = drag handle (`Icons.drag_indicator_rounded`, 48x48 target), phase icon + name (Body 15 / w600) (the long `DietPhase.subtitle` is not repeated here); duration stepper (`-` / "{n} weeks" / `+`, each 48x48, range 2 to 52 weeks, step 1), trailing delete `IconButton` (48x48, `Icons.delete_outline_rounded`, `secondary`).
- Reorder must also work without drag: each row exposes semantics custom actions "Move up" / "Move down".
- Delete is immediate within the draft (non-destructive until accepted) and shows SnackBar "Phase removed" with action "Undo". Removing the last remaining phase is blocked: delete button disabled on a single row.
- Below the list: `OutlinedButton` "Add phase" opens a picker row of five `HxPill`s (`DietPhase` labels); restricted ones disabled. Below that `TextButton` "Reset to suggestion" (confirm dialog).
- Each row shows the derived tempo as a Label ("About 0.5 kg per week") and, when `PhysiqueTempoPolicy` capped the preset, an extra Label "Paced to a safe weekly rate" in `secondary`.
- Dirty-dismiss: dragging the sheet down with unsaved edits asks "Discard changes?" (Keep editing / Discard).

### Add check-in (S3, PHYS-02/06/07)

`HxSheet` title "Add check-in", steps shown as plain text "Step {i} of 4" (Label), no stepper graphic.

1. **Pose**: three `HxPill`s Front / Side / Back (reuse the pose ids already used by `measurements_view.dart`: `front`, `side`, `back`); default `front`. Then two buttons: `FilledButton` "Take photo" and `OutlinedButton` "Choose from library".
2. **Privacy options**: preview (max height 320, `HxRadius.mdAll`), `SwitchListTile` "Blur my face" (default = last used, first use off), subtitle "Happens on your device. The original face is never saved." Always-on line (Label, `secondary`): "Location and camera details are removed from every photo." `FilledButton` "Continue".
3. **Consent + analyse** (shown only until consent version is accepted, reusing the existing `dream_physique_images_v1` consent mechanism): Body copy per Copywriting; `FilledButton` "Analyze my progress", `TextButton` "Save photo without analysis".
4. **Result**: verdict block (above), `FilledButton` "Done". The check-in is persisted before this step renders; "Done" only dismisses.

Processing states (inline, centred, `CircularProgressIndicator.adaptive` 24 + Label): "Removing location data...", "Checking for faces..." (only when blur on), "Comparing with your baseline...". Controls disabled while any step runs; the sheet cannot be dismissed mid-analysis (`isDismissible` false, back button shows no-op SnackBar "Hang on, almost done"). If the OS killed the activity during capture, the flow resumes at step 2 via `PendingAiScanContext` (`physiqueCheckin`), no copy needed.

Zero faces found while blur requested: dialog (S6) with three actions, never claims "blurred".

### 7-day cap (PHYS-06, D-13)

- Entry button on S1: when eligible `FilledButton` "Add check-in" (primary accent). When capped: the button is **disabled** (`onPressed: null`) with label "Next check-in available {EEE, MMM d}" and a `Icons.schedule_rounded` leading icon. Disabled style = theme default; text must still reach 4.5:1 against its fill (do not rely on theme disabled alpha: set `foregroundColor: onSurfaceVariant`, `backgroundColor: surfaceVariant`).
- The same date is exposed as `Semantics(label: 'Check-in locked until {full date}')`.
- While a submit is in flight the button is disabled and shows the processing label (prevents double-submit).
- If the repository throws `CheckInTooSoonException` anyway (two devices, race), close any open sheet, show SnackBar with the cap-error copy and refresh the card. Never swallow it.
- A first check-in on a brand-new goal is always eligible.

### Phase advancement (S1, D-02)

Accept: pops the current phase to "Done", marks next "Current", SnackBar "Moved to {Phase}. Review your nutrition targets." with action "Set targets" (push `AppRoutes.nutritionTargets`, `extra: DietPhase`). Writes nothing to targets. Postpone: see Active phase card.

### New goal (S6, D-03)

Triggered from the existing Dream Physique analysis save path when an active goal exists. Dialog "Start a new goal?" (copy below). Confirm archives the old goal; cancel leaves everything as is.

### Legacy migration notice (S9, D-08)

Runs once at startup, non-blocking. SnackBar on success: "Your progress photos now live in your private Dream Physique goal." Partial failure SnackBar (once): "{n} older photos couldn't be recovered." No action. Never a blocking dialog.

### Navigation and entry (S7)

- `DreamPhysiqueSummaryCard`: when an active goal exists, card body tap opens `AppRoutes.dreamPhysiqueProgress`; the existing "Tap to start a new analysis." line becomes a `HxTextPill` "New analysis" (`onTap` pushes `AppRoutes.dreamPhysique`) and the card gains a Label "View progress" on the chevron row. With no goal the card behaves exactly as today. Keep the existing `Key('dream-physique-summary-card')` and its tests green. Edits are additive; do not restyle the card's literal colours in this phase (UI-rework Phase 9 owns that sweep), but any NEW code inside it uses `context.hx`.
- Back from S1 returns to Profile. No change to `HxNavBar`; the route is a pushed page (frosted header from `HxScreenShell`, no glow).

### Photo display rules

- Thumbnails resolve relative path -> documents dir at read time, `Image.file` with `cacheWidth` set to 2x the display width, `fit: BoxFit.cover`, `gaplessPlayback: true`.
- Missing file (legacy cache path gone): placeholder `surfaceVariant` fill, `Icons.image_not_supported_outlined` 24 in `tertiary`, Label "Photo unavailable". Never throw, never hide the row.
- Full-screen photo viewing is out of scope (deferred); thumbnails are not tappable except in S4 rows opening the check-in detail inside the sheet.

## Typography

Exactly 4 sizes and 2 weights across all new Phase 23 widgets. Weights in use: regular 400 and semibold 600. Do NOT use w500, w700, w800, w900 (the older Dream Physique cards use w800/w900; do not copy them). Styles come from `Theme.of(context).textTheme` with explicit `fontWeight` and `height` overrides, centralised in one feature-local helper (`physique_text.dart`, static styles) so the contract is enforced in one place. Shared components keep their own internal weights (`HxPill` selected state, `HxTopTabs`, `HxScreenShell` title); those are accepted.

| Role | Size | Weight | Line Height | Source style / usage |
|------|------|--------|-------------|----------------------|
| Display | 24 | 600 | 1.2 | `headlineSmall` (Space Grotesk, tabular): phase name, latest chart value |
| Heading | 17 | 600 | 1.2 | `titleMedium`: card titles, sheet section titles |
| Body | 15 | 400 (600 for emphasised row titles) | 1.5 | `bodyMedium` / `titleSmall`: descriptions, reasons, buttons use theme (16 / w600 already defined in `AppTheme` button styles, accepted as component-internal) |
| Label | 13 | 600 for chip/status text, 400 for captions and axis ticks | 1.5 | `bodySmall`/`labelMedium` with override: chips, captions, footnotes, chart ticks |

Numerals (weights, dates, week counts) use tabular figures (already enabled for `headlineSmall`; add `FontFeature.tabularFigures()` to Body/Label numerals in stat rows). Text must reflow, not truncate, up to 200% text scale: no fixed-height text containers; `maxLines` only on single-line list subtitles with `TextOverflow.ellipsis` in S4/S5 rows.

## Color

All values are tokens from `HxColors`; hex shown for the default Classic Blue theme only as a reference (dark / light). Contract holds for all 5 themes.

| Role | Token | Classic Blue dark / light | Usage |
|------|-------|---------------------------|-------|
| Dominant (60%) | `background` / `backgroundGradient` | #091322 / #E4EFFC | Page background behind `HxScreenShell` |
| Secondary (30%) | `surfaceContainerLowest` (cards via `HxCard`), `surfaceContainer` (sheets, dialogs, tooltips), `surfaceVariant` (tracks, disabled fills, inputs) | #111824 / #F5F9FF; #161E2E / #FFFFFF; #202A3C / #DDE9F7 | Cards, sheets, bar tracks |
| Accent (10%) | `primary` (fills), `primaryText` (text/icons) | #0A84FF (fill), #4DA3FF / #0063CC (text) | See reserved list |
| Domain (nutrition) | `domainNutrition` | #30D158 / #1E7A34 | Phase-related surfaces only: active phase card accent, phase icon chips, progress bar fill, completed timeline nodes, bodyweight target band, advance-prompt tint |
| Domain (training) | `domainTraining` | #0A84FF / #0A84FF | Strength and Training-level chart lines only |
| Status | `success`, `warning`, `secondary` | per theme | Verdict chip states (on track / off track / inconclusive) |
| Destructive | `danger` | #FF453A / #C7261C | Destructive dialog confirm buttons only |

Accent reserved for (explicit, exhaustive):
1. The single filled primary `FilledButton` visible per state: "Add check-in", "Move to {Phase}", "Accept roadmap"/"Save roadmap", "Analyze my progress", "Start new goal".
2. The selected segment of the `1M / 3M / All` `HxTopTabs`.
3. The selected `HxPill` states (pose picker, lift selector, phase picker).
4. The "Current" node ring in the roadmap timeline.
5. Text-button labels (via `primaryText`, theme default) and the focus border on inputs.

Accent is NOT used for: verdict states, chart lines, band fills, icons in cards, or decorative tints. `danger` is never used for "Off track".

Contrast: any text on a tinted (alpha 0.14) fill is `onSurface`, never the tint colour itself. Icons carrying meaning are at least 3:1, text at least 4.5:1, verified in light and dark for every `AppColorTheme` (pinky and sunny yellow are the tightest for `warning`).

## Accessibility and Motion

- Every tappable is at least 48 x 48 logical px. Pills/chips extend their hit area, not their visual size.
- Verdict, phase status and cap state are always text + icon, never colour alone. Chart plots are paired with the text summary line.
- All new interactive widgets set `Semantics`/tooltips; the drag-reorder rows expose "Move up/Move down" custom actions; disabled cap button exposes the unlock date.
- Layout survives 200% text scale and the narrowest supported width (320 dp): cards wrap, rows become two lines, the lift selector scrolls horizontally.
- Motion: `HxMotion.fast` for chip/pill state, `HxMotion.base` for colour/opacity, `HxMotion.slow` for the range-bar and chart reveal. All collapse to zero when `MediaQuery.disableAnimations` is true. Haptics: `Haptics.selection()` for range/lift/pose changes (already inside `HxPill`/`HxTopTabs`), `Haptics.light()` on Accept roadmap, Move to phase and check-in done. No success confetti, streaks or celebratory animation (no negative or manipulative gamification; Phase 24 owns XP).
- Loading: card-level `CircularProgressIndicator.adaptive` (24) centred in the card for provider loading; charts reserve 200 height with a flat `surfaceVariant` block so layout does not jump. Provider errors render a Body line "Couldn't load this right now." with `TextButton` "Try again" that invalidates the provider.
- Light and dark, all five `AppColorTheme`s, each verified by the checker for the S1 screen, both sheets, and the verdict states.
