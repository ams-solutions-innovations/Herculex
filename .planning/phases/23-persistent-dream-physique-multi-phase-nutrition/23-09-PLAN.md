Decisions recorded (RESEARCH Runtime State Inventory + Open Questions):
- The legacy goal's `startedAt` is the OLDEST history entry's `analyzedAt`, so if the user already has a newer active goal when the migrator runs, `reconcileSingleActive()` archives the legacy goal rather than the live one.
- Every history entry becomes an `analysis` assessment whose `summaryJson` is the entry's existing `toJson()`; the newest entry defines the goal's style, timeframe, months and target BF.
- Legacy photos become `role = 'baseline'`, `source = 'legacy_import'`, `legacyRef = 'progress_photo:<id>'`, `assessmentId` null. They are never given role `checkin` (that role belongs to `recordCheckIn` alone).
- The `DreamPhysiqueNutritionPreference` (selected direction / dismissed) is DROPPED, not migrated: the roadmap generator derives the first phase deterministically and the existing direction card keeps reading its own preference. Documented, per RESEARCH.
- A user with legacy photos but no summary history gets no goal (a goal needs a target); their photos stay in `progress_photos` untouched and the migrator is not marked done, so it re-checks cheaply on later launches. Known limitation, noted in the summary and Plan 17.
- Measurements-screen progress-photo capture still writes the legacy table (out of scope; flagged in Plan 17).
- Also adds `tdee_estimates` and `herculex_ai_program_briefs` to the wipe list: both are synced user tables that the wipe currently misses (an account-deletion completeness gap found while editing this list).
