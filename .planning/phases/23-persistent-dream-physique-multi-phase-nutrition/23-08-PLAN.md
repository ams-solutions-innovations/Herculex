Wire contract (from Plan 04, authoritative): request `kind: 'physique_checkin'`, `baselineImages` (1-3 of `{mimeType, data(base64)}`), `currentImages` (exactly one), `checkinContext {phase, weeksInPhase, weightTrendKgPerWeek}`, `userNote`, `privacyConsent {version: 'dream_physique_images_v1', granted: true}`. Response `{result: {directionBand: {low, high}, confidence: 'low'|'medium'|'high', reason, limitations[]}, privacy, provenance: {modelVersion, knowledgeVersion}}`. Dream-physique additions (optional): `currentBfRangeMin`, `currentBfRangeMax`, `assessmentConfidence`.

Design decision (planner): do NOT add `analyzePhysiqueCheckIn` to the `GeminiBackend` interface. Eight test files declare `implements GeminiBackend` fakes (`block_builder_view_test`, `body_fat_ai_service_test`, `dream_physique_service_test` x2, `gemini_food_analyzer_service_test`, `herculex_ai_brief_service_test`, `supplement_ai_service_test`); adding an abstract member would break every one. Instead add `abstract interface class PhysiqueCheckInBackend`, make `UnconfiguredGeminiBackend` and `SupabaseGeminiBackend` implement both interfaces, and expose `physiqueCheckInBackendProvider` which returns the existing backend when it implements the new interface and `UnconfiguredGeminiBackend` otherwise. Tests of the check-in flow override this provider with a fake.

Existing facts: `SupabaseGeminiBackend._invoke` converts a `FunctionException` body `{error: '...'}` into `Exception('<message>')`; the 429 quota message from the edge function contains "are used up"; images are passed as `{'bytes': List<int>, 'mimeType': String}` maps and encoded by `_imagePayload`; `_resultWithProvenance(data)` returns `(result, provenance)`; `dreamPhysiqueImageConsentVersion = 'dream_physique_images_v1'` is exported from the same file.
