# Phase 19 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This is a Flutter/Riverpod app, not a web/shadcn stack — the "Design System" section
below documents the existing `lib/design_system/` tokens and components this phase
must reuse, not a component-library preset. No new tokens, colors, or type sizes are
introduced by this phase; every value below already exists in the app theme.

`ExerciseReplacementSheet` extraction target file if it can cleanly reuse `context.hx`
directly — new file, no existing convention to preserve. Either choice is acceptable;
what is NOT acceptable is a raw hex literal anywhere.

## Typography

Scoped to only the roles this phase's new/changed UI actually introduces or
touches — reusing the app's existing `TextTheme` exactly (`app_theme.dart`
`_buildTextTheme`); no new type styles are defined:

| Role | Size | Weight | Line Height / Notes |
|------|------|--------|-------------|
| Week dropdown value / section title (`titleMedium`) | 17px | 600 | `Manrope`, letterSpacing -0.2 |
| Wave-strip label, primary line — "Week N of M" (`titleSmall`) | 15px | 600 | `Manrope`, letterSpacing -0.1 |
| Wave-strip label, secondary line — "Exercise wave X of Y · Weeks A–B" (`labelMedium`) | 13px | 500 | `Manrope`, color `secondary` |

3 sizes, 2 weights — within the dimension's 4-size/2-weight cap.

The Week/Wave label pair (EDIT-01) uses `titleSmall` for "Week N of M" (primary) and
`labelMedium` for "Exercise wave X of Y · Weeks A–B" (secondary, directly beneath) —
this satisfies D-05/the spec's requirement that the two labels are visually distinct
and never merged into one string.

**Reused, unchanged roles — not part of this phase's size/weight budget** (listed for
context only; no executor action needed, do not re-declare or extend these):

- Guide page title (`headlineSmall`, 24px/600) — `program_method_guide_view.dart` is
  visually unchanged per D-06 ("no new visual chrome"); only its `weeks` data list grows.
- `ExerciseReplacementSheet` body copy, scope descriptions (`bodyMedium`, 15px/400) —
  extraction-only per D-02, "visually and behaviorally unchanged" from
  `program_review_view.dart`.
- Fine print / tooltip / badge text (`labelSmall`, 12px/500) — no new label in this
  phase uses this role; the "Replace this exercise" tooltip and empty-state strings
  render via existing surrounding widget styles, not a new `labelSmall` usage.

## Color

Reuse `HxColors`/`AppColors` tokens exactly (`hx_colors.dart`) — no new colors:

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `surfaceContainer` / page `backgroundGradient` | Scaffold background, week card fill |
| Secondary (30%) | `surfaceContainerLowest` | Nested rows (day rows, exercise list rows, guide week cards), sheet body |
| Accent (10%) | `primary` | Week dropdown active state, wave-strip active dot/chip, "This wave" recommended pill, guide week-row leading avatar, per-exercise replacement trigger icon |
| Destructive | `danger` | Not used in this phase — no destructive actions are introduced (day-level "Remove day" already exists and is unchanged; it uses `secondary`, not `danger`, matching existing `_DayRow` styling — out of scope to change) |

Accent (`primary`) reserved for: the active/selected Week dropdown value, the
wave-strip's current-wave indicator, the "This wave" (recommended) scope pill in
`ExerciseReplacementSheet`, the per-exercise replacement affordance icon added to each
exercise row, and the guide view's week-number avatar/bullet markers. Accent is never
used for plain body text, card backgrounds, or the day-level link icon (which keeps
its existing `primary` tint too — pre-existing, not newly introduced by this phase).

`isDeload`/phase-tint pattern (existing in `_WeekCard`) — deload weeks use `tertiary`
tint instead of `primary`; carry this same convention into the new single-active-week
Week dropdown / wave-strip view so a deload week reads the same way it does today.

## Visual Hierarchy

Primary focal point of the retrofitted week view, in descending order of visual
weight:

1. **Week dropdown** — the top-of-view control (`titleMedium`, 17px/600, `primary`
   accent when active). This is what the eye lands on first and what the user taps to
   navigate; it owns the top of the hierarchy.
2. **Active week's exercise/day list** — the bulk of the view's real estate and the
   thing the user is actually editing (existing `_WeekCard`/`_DayRow` styling,
   unchanged). Visually dominant by area even though it isn't the highest-contrast
   element.
3. **Wave-strip label** — a quiet, secondary caption directly beneath the Week
   dropdown (`titleSmall`/`labelMedium`, no card chrome of its own). It is
   explanatory context, not a navigation control, and must not compete with the
   dropdown or the exercise list for attention — this is why it renders as plain
   stacked text rather than a bordered chip or its own card.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Week dropdown label | `Week {N} of {M}` (e.g. "Week 3 of 8") |
| Wave-strip label | `Exercise wave {X} of {Y} · Weeks {A}–{B}` (e.g. "Exercise wave 2 of 4 · Weeks 3–4") — rendered as its own line/chip, never concatenated with the Week label |
| Per-exercise replacement trigger (icon tooltip) | `Replace this exercise` |
| Replacement sheet title (reused as-is) | `Choose a replacement` |
| Replacement sheet subtitle (reused as-is) | `Biomechanically similar options for {exercise name}.` |
| Scope section label (reused as-is) | `Apply replacement to` |
| Scope pill labels (reused as-is) | `This wave` (Recommended) / `This and future waves` / `Entire block` |
| Scope helper copy — this wave (reused as-is) | `Recommended — changes only this continuous run of the exercise.` |
| Scope helper copy — this and future (reused as-is) | `Keeps earlier waves and replaces this wave plus all later ones.` |
| Scope helper copy — entire block (reused as-is) | `Uses this replacement for every week in the block.` |
| Empty state — no exercises in day (reused as-is) | `No template — sessions will be empty` |
| Empty state — no replacement candidates (reused as-is) | `No compatible alternatives are available yet.` |
| Guide "Example block" section heading (reused as-is) | `Example block` |
| Guide week row (new, per D-06) | Title: existing phase label per model (e.g. "Accumulation", "Build", "Max Effort A"); description: existing per-week sentence style already used (imperative, one sentence, e.g. "Add a small load or rep improvement while volume stays steady."). Weeks without a hand-authored milestone entry today (e.g. Linear weeks 5–8) get an equivalent one-sentence description in the same voice — planning/implementation fills exact wording per D-06's discretion note, but it must never be a placeholder like "TBD" or a repeated verbatim duplicate of an adjacent week's description. |
| Destructive confirmation — delete block (reused as-is, unchanged this phase) | `Delete this block?` / `Every scheduled session in "{name}" is removed, including completed ones. Your workout history and templates are not touched.` |

No new destructive actions are introduced by Phase 19. Per-exercise replacement is
non-destructive (undoable by replacing again) and does not require a confirmation
dialog — it already follows this pattern in `program_review_view.dart` today (tap →
immediate apply, no "Are you sure?").

## Component & Interaction Notes (Flutter-specific, supplements template)

- **Week dropdown (EDIT-01):** Build with a standard `DropdownButton`/`DropdownButton2`-
  style widget wrapped in the existing `HxPill`/card chrome rather than inventing a new
  dropdown shell (per CONTEXT.md's "Claude's Discretion" — widget choice is open, but it
  must render "Week N of M" as its displayed value, and changing it must not require a
  full-screen navigation — an inline/anchored dropdown or `showModalBottomSheet` list is
  fine, a new `MaterialPageRoute` push is not, to keep it a one-tap switch consistent
  with how the sheet-based replacement flow behaves).
- **Wave-strip indicator (D-05):** A single-line label directly beneath the Week
  dropdown, not a separate scrollable widget/strip of dots per se (the "strip" in
  CONTEXT.md refers to the concept, not a required visual chip-rail) — `labelMedium`,
  `secondary` color when inactive context, matching the existing pattern of secondary
  metadata directly under a card title (see `_ProgramTrackingCard`'s metric row for the
  established layout rhythm).
- **Per-exercise replacement trigger (EDIT-02):** Add a small icon button
  (`Icons.swap_horiz_rounded` or `Icons.tune_rounded`, 18–20px, `primary` tint,
  `visualDensity: VisualDensity.compact` — matching the existing `_DayRow` icon-button
  sizing) to each exercise row rendered in the new single-active-week view. It sits
  alongside the exercise text, not replacing the existing day-level link icon (D-03) —
  both are visible simultaneously on a day that has a template linked and exercises
  populated.
- **Extracted `ExerciseReplacementSheet` (D-02):** Visually and behaviorally unchanged
  from its current `program_review_view.dart` implementation — this is a file-move/
  extraction, not a redesign. Both call sites (`program_review_view.dart` pre-commit,
  retrofitted `block_detail_view.dart` post-commit) must render pixel-identical sheets.
- **Guide 8-week list (D-06):** Keep the existing `Card` + `ListTile` + `CircleAvatar`
  week-number-badge rendering (`program_method_guide_view.dart` lines 54–68) — only the
  `weeks` data list grows from 4 milestone entries to 8 literal entries per model
  (except `PeriodizationModel.none`, where CONTEXT.md leaves the exact row count to
  planning discretion). No new visual chrome for this section.
