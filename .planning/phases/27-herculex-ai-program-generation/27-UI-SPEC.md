# Phase 27 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Platform note:** Herculex is Flutter/Dart (Material widgets, custom `design_system/` token layer), not a web/shadcn stack. This contract adapts the standard UI-SPEC template to that reality — "Design System" below documents the Flutter token system instead of a shadcn preset, and "Registry Safety" is not applicable (no component registry in this codebase).

**Scope reminder (from 27-CONTEXT.md D-03):** No new screen. This phase adds a 4th tile to the existing Step-1 mode picker in `block_builder_view.dart`, a "Generate"/"Regenerate" action, a rejection-message state, and a per-day AI rationale element in `program_review_view.dart`. Every visual spec below is either "reuse this existing widget/pattern verbatim" or "new element modeled directly on this sibling" — this phase does not introduce new visual language.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (no shadcn/component registry — Flutter custom design system) |
| Preset | not applicable |
| Component library | `lib/design_system/` — `HxColors` (tokens/hx_colors.dart, `ThemeExtension`), `HxSpace`/`HxRadius` (tokens/hx_geometry.dart), `HxMotion` (tokens/hx_motion.dart), `AppTheme` (theme/app_theme.dart, builds `TextTheme`/component themes from `HxColors`). Widget components: `HxSheet`, `HxCard`, `HxScreenShell`, `PremiumButton` (design_system/components/). |
| Icon library | `Icons.*` (Material, `_rounded` suffix family exclusively — e.g. `Icons.auto_awesome_rounded`, `Icons.check_circle_rounded`, `Icons.info_outline_rounded`) |
| Font | Body: `Manrope` (`AppTheme.fontBody`). Display/headline: `SpaceGrotesk` (`AppTheme.fontDisplay`). Both already registered in `AppTheme`; this phase introduces no new typeface. |

**Token access rule for this phase (new code, not the surrounding legacy code):** Use `context.hx.<token>` (the `HxColorsContext` extension), never the `AppColors` static shim and never a literal `Color(0xFF...)`. `block_builder_view.dart` and `program_review_view.dart` currently still import `design_system/theme/colors.dart` and call `AppColors.*` throughout (pre-`context.hx` code, not yet swept by the UI-rework Phase 9 AppColors-shim-removal effort — see `CLAUDE.md`). Do not extend that pattern. Every new widget/section this phase adds — the 4th mode tile, the Generate/Regenerate button, the rejection banner, the per-day AI rationale card — must read colors via `context.hx.*`. This is a deliberate scope-local exception to "match the surrounding file exactly": match the surrounding file's *layout and spacing conventions*, not its `AppColors` call sites.

## Typography

Declared roles for this phase's new UI — all pulled directly from the existing `AppTheme.textTheme` (`lib/design_system/theme/app_theme.dart`), no new sizes/weights are introduced:

| Role | Size | Weight | Line Height | Maps to |
|------|------|--------|-------------|---------|
| Section label | 12px | 500, uppercase, letterSpacing 1.1 | 1.2 (theme default) | `theme.textTheme.labelSmall` — reuse `_sectionLabel()` verbatim for any new section heading |
| Body / caption | 13px | 400 | 1.3 (theme default) | `theme.textTheme.bodySmall` — mode-tile subtitle, rejection-message body, per-day rationale text |
| Title / emphasis | 15px | 700 (explicit `.copyWith(fontWeight: FontWeight.w700)`) | 1.3 (theme default) | `theme.textTheme.titleSmall` overridden — mode-tile title ("Herculex AI"), rejection-banner heading, rationale-card heading |
| Step heading (unchanged, inherited) | 24px | 700 | 1.2 (theme default) | `theme.textTheme.headlineSmall` via the existing `_title()` helper — Step 1's "How do you want to build?" heading is unchanged by this phase |

Weights used: **400** (regular, body/caption text) and **700** (bold, titles/emphasis/headings). Do not introduce a third weight for this phase's new elements — the underlying `titleSmall`/`bodySmall` theme styles already carry the correct family (`Manrope`) and letter-spacing; only override `fontWeight`, never `fontSize` or `fontFamily`.

## Color

60/30/10 split, expressed as `context.hx.<token>` names (resolve to theme-appropriate hex per the active `AppColorTheme`/brightness — this app ships 5 selectable palettes plus light/dark, so no single hex is "the" dominant color; see `HxColors` for all 10 palette instances):

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `context.hx.background` / `backgroundGradient` | Screen background behind the mode picker and review screen (inherited from `HxScreenShell`, unchanged) |
| Secondary (30%) | `context.hx.surfaceContainerLowest` (unselected mode tile fill) / `context.hx.surfaceContainer` (rationale card fill) | Mode-tile default state, per-day rationale card background |
| Accent (10%) | `context.hx.primary` | **Reserved for:** (1) the Herculex AI mode tile's selected-state border + tint (`primary.withValues(alpha: 0.10)` fill, full-opacity border — exact match to the existing `_radioCard` selected treatment), (2) the "Generate"/"Regenerate" `PremiumButton` (`isPrimary: true`, already resolves to `theme.colorScheme.primary`), (3) the `Icons.auto_awesome_rounded` icon on the AI mode tile and on the per-day rationale card heading (mirrors the existing Dream Physique `auto_awesome_rounded` + `primary` pairing used everywhere else AI-derived content appears in this file), (4) the per-day rationale card's left accent/icon only — never its body text color |
| Second semantic (warning) | `context.hx.warning` | Rejection-message banner (D-05): icon + heading use `warning`, never `danger`. A rejected brief with fallback-to-Smart/Guided is an expected, recoverable degradation — not a destructive/irreversible action — so it reads as "heads up," matching the existing `warning` token's use elsewhere in the app (never introduced as a literal color) |
| Destructive | `context.hx.danger` | Not used by this phase — there is no destructive action in the Herculex AI mode/brief/rationale flow. Listed only because the template requires the row; do not add a delete/discard action that wasn't asked for. |

Accent reserved for: the 4 bullet points above — the AI mode tile (icon + selected border/fill), the Generate/Regenerate button, the rationale card's icon/heading accent. Never apply `primary` to body text, dividers, or any element outside that list.

| Element | Copy |
|---------|------|

You review and confirm every choice."** (mirrors the existing 3 subtitles' sentence shape at `block_builder_view.dart:487-492`: one sentence stating the mechanism, one stating the user's control) |
| Generate button (initial) | **"Generate with Herculex AI"** — `PremiumButton(icon: Icons.auto_awesome_rounded)`. Not auto-fired on mode select (D-04); this button is the explicit trigger, visually distinct from the step's normal "Continue" footer button — render it inline within Step 1 once the Herculex AI tile is selected, not in the pinned footer, so "Continue" still means "move to Step 2" without accidentally consuming a quota unit. |
| Generate button (loading) | **"Generating…"** with the button disabled (same `_saving ? () {} : …` no-op-while-busy pattern already used by the footer's `PremiumButton`) |
| Regenerate action | **"Regenerate"** — a secondary/outlined action (not full-width `PremiumButton(isPrimary: true)`) shown once a brief has already been applied, alongside a compact "Applied ✓" or similar status indicator on the AI tile (mirrors the existing Dream Physique tile's `status: 'Active'` chip pattern at `_builderInputCard`) |
| Rejection message (D-05, guardrail/schema violation) | Heading: **"Herculex AI suggestion couldn't be used"**. Body: the specific reason, verbatim from the validator — e.g. *"The AI suggested a 6-day PPL with Max Effort, which exceeds the safety limit."* Never a generic "Something went wrong." Footer line: **"Showing the recommended Smart/Guided setup instead — you can still adjust anything below."** (states the automatic fallback per D-05, so the user never hits a dead end) |
| Offline / unconfigured degradation (AIP-05) | **"Herculex AI isn't available right now — continuing with the Smart/Guided recommendation."** (one shared message covers offline and unconfigured; do not expose "unconfigured" as a user-facing technical detail — that's an operator problem, mirrors the existing `_analysisErrorMessage`'s pattern of translating a 401/unconfigured state into an actionable, non-alarming sentence rather than showing the raw exception) |
| Over-quota degradation (AIP-05) | **"Today's Herculex AI program briefs are used up — try again tomorrow. Continuing with the Smart/Guided recommendation."** (directly mirrors the existing server-side copy shape at `supabase/functions/gemini-analyze/index.ts:240`: `` `Today's ${featureName} (${quota.limit}/day) are used up — try again tomorrow${manualFallback}.` `` — reuse that exact sentence structure, do not invent a new one) |
| Per-day AI rationale card heading (AIP-04, D-09) | **"Why this day"** (short, per-day-scoped label distinguishing it from the existing per-slot `EmptySlotNotice`/`SelectionExplanation` rationale it sits beside — never reuse "Why this exercise" or similar per-slot phrasing) |
| Per-day AI rationale body | The brief's own `dayRoles[].rationale` string, verbatim — this widget renders, never re-derives or truncates the text (same non-negotiable rule `EmptySlotNotice`'s doc comment states for its own `reason` field) |
| Destructive confirmation | Not applicable — no destructive action in this phase's scope |

## States Checklist (for gsd-ui-checker / gsd-executor)

| State | Requirement |
|-------|-------------|
| Mode tile — unselected | `surfaceContainerLowest` fill, `outlineVariant` @ 35% border, 1px — matches sibling `_radioCard` unselected state exactly |
| Mode tile — selected | `primary` @ 10% fill, `primary` border, 1.5px — matches sibling `_radioCard` selected state exactly |
| Generate — idle | `PremiumButton(isPrimary: true, text: 'Generate with Herculex AI', icon: Icons.auto_awesome_rounded)` |
| Generate — loading | Button text → "Generating…", `onTap` → no-op (disabled-by-noop, matching the footer's existing `_saving` pattern — this codebase does not use Flutter's native `disabled` styling for this button, stay consistent) |
| Generate — success | Brief pre-fills Step 1–5 pickers (D-03); tile shows "Applied" status chip; a "Regenerate" secondary action appears |
| Generate — rejected (D-05) | Rejection banner (warning token) renders inline below the AI tile; Step 1–5 pickers show the existing Smart/Guided recommendation values (automatic fallback, never blank/dead state) |
| Generate — offline/unconfigured (AIP-05) | Single shared degradation message (Copywriting § above) renders in place of the rejection banner; same fallback-to-Smart/Guided behavior |
| Generate — over quota (AIP-05) | Quota-specific degradation message (Copywriting § above); same fallback behavior |
| Review screen — per-day rationale present | "Why this day" card renders per day, `primary`-accented, positioned in `_DayCard` alongside (not replacing) any existing `EmptySlotNotice` for that day |
| Review screen — per-day rationale absent (non-AI-built program) | Card does not render at all — this element is conditional on `source == 'herculex_ai'`, never shown for manual/smart/guided programs |
