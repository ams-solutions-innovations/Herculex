<objective>
Add generateProgramBrief() to the GeminiBackend 3-tier interface (abstract interface, UnconfiguredGeminiBackend, SupabaseGeminiBackend), the client-side counterpart to plan 27-06's new "program_brief" Edge Function kind. Per RESEARCH.md Pitfall 2, the existing _resultMap() helper silently discards the wire response's provenance (modelVersion/knowledgeVersion) - every one of the 8 existing callers only reads data['result']. Since D-08 requires persisting both modelVersion and knowledgeVersion, this plan adds a NEW method (_resultWithProvenance()) rather than changing _resultMap()'s contract for the other 8 unrelated callers.

Because GeminiBackend is an abstract interface class, adding a new abstract method to it is a breaking change for every class that directly "implements GeminiBackend" (as opposed to extending UnconfiguredGeminiBackend) - four existing test files each declare such a fake. This plan updates all four alongside the interface change so the full suite keeps compiling.

Purpose: the only client-side entry point that reaches the program_brief Gemini path; plan 27-09's HerculexAiBriefService calls this method exclusively.
Output: GeminiBackend.generateProgramBrief() implemented across all three classes, returning a (Map<String, dynamic> result, Map<String, dynamic> provenance) record, plus every existing test-only GeminiBackend fake updated to implement it.
</objective>
